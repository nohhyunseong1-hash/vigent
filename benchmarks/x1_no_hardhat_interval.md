# [X-1] NO-Hardhat 재현율 — 구간 보고 (dev 74장, 운영 경로, 2026-08-10)

## 배경

[X-0] 검수자 정성 판정: 놓친 NO-Hardhat 40건 중 **대부분**은 크롭만으로도 안전모 착용/맨머리
구분이 불가능함(`benchmarks/s1_miss_montage.md` §[X-0]). 이 GT들은 정답 자체가 불확실하므로
단일 재현율 수치가 성립하지 않는다 — 두 값을 함께 낸다.

## 결과 (`benchmarks/x1_no_hardhat_interval.py` 실측)

| | 값 | 근거 |
|---|---|---|
| dev NO-Hardhat 전체 GT | 54건 | 라벨 실측 |
| TP(적중) | 14건 | 운영 경로(person+ppe 앙상블) 실측 |
| FN(놓침) | 40건 | = judge sheet 40건과 좌표 매칭 100% 일치(교차검증) |
| **하한**(전체 GT 기준) | **25.9%** (14/54) | 현행 |
| **상한**(ambiguous 40건 채점 제외) | **100.0%** (14/14) | ambiguous 제외 시 |

**참값은 [25.9%, 100.0%] 구간으로 추정한다.**

## ★해석 시 주의(규칙7) — 상한 100%가 뜻하는 것

상한이 정확히 100%인 것은 우연이 아니라 **정의상 당연한 결과**다 — judge sheet의 40건이
정확히 "이번 dev 측정에서 놓친 전체 NO-Hardhat(FN)"이므로, 그 40건을 전부 채점에서 빼면
남는 GT(14건)는 전부 TP였던 것들이라 재현율이 자동으로 100%가 된다. 이건 "모델이 완벽하다"는
뜻이 아니라 **"25.9%와 100% 사이의 간극 전부가 이 특정 40건의 라벨 신뢰도 문제로 설명된다"**는
뜻이다.

또한 [X-0]의 검수자 판정은 "대부분"이지 "전부"가 아니었다 — 개별 40건 중 일부는 실제로
구분 가능했을 수 있다(개별 O/X 목록이 없어 몇 건인지는 모른다, 규칙7). 즉 **진짜 상한은
100%보다 약간 낮을 가능성이 있으나, 이 자료만으로는 그 정확한 값을 알 수 없다.**

## 사용 규칙

이후 모든 리포트에서 NO-Hardhat 재현율은 **[25.9%, 100.0%] 구간으로 인용**한다(단일 수치
"25.9%"만 인용 금지 — 규칙7). ambiguous 목록은 `data/field_eval/ambiguous_no_hardhat.json`에
플래그로 보관(GT 라벨 파일 자체는 미수정).
