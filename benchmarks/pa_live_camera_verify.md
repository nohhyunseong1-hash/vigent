## 0. 측정 조건

| 항목 | 값 | 비고 |
|---|---|---|
| 카메라 | Tapo 실카메라(192.168.0.5, RTSP stream1) | 카메라 자체 지연 ~1.4s(별건, `tapo_e2e_validation.md` §3) |
| 검출 배치 캐던스 | **2.3 fps (간격 중앙값 0.43초)** | 확대뷰 focus 미사용 상태(풀세트 캐던스) |
| 검출 슬롯 | person + ppe + fire_smoke (RF-DETR) | fire_smoke 는 이날 실모델 복구 완료(LOADED) |
| 트래커 | ByteTrack(person 슬롯 한정) | 스폰 임계 = person 운용 임계 0.40 자동 연동 |
| `BYTETRACK_LOST_BUFFER` | 30 프레임 | 아래 환산 관계 참고 |

**버퍼 환산 관계(중요)**: `lost_track_buffer=30`을 이 캐던스로 나누면 **30 ÷ 2.3fps ≈ 13초**다.
아래 6b에서 **11.55초 부재까지 동일 id 가 복원**된 관측이 이 환산과 모순되지 않는다.
★단, **라이브러리 내부 환산식(frame_rate 스케일링 여부)은 코드로 확인하지 않았다** — "30프레임을
그대로 쓴다"는 해석이 관측과 정합할 뿐이며, 13초는 검증된 상한이 아니다(11.55초까지만 실측).

단, 단독 보행은 가장 쉬운 조건이므로 이 결과만으로 다인 상황을 주장할 수 없다.

## 2. 6b — 프레임 이탈·재진입 (부재 5회)

| 부재# | 부재 시간 | 직전 id | 재진입 id | 판정 |
|---|---|---|---|---|
| 1 | 6.01초 | 10000001 | 10000001 | 동일 id 복원 |
| 2 | **11.55초** | 10000001 | 10000001 | **동일 id 복원** |
| 3 | 2.88초 | 10000001 | 10000001 | 동일 id 복원 |
| 4 | 1.86초 | 10000001 | 10000001 | 동일 id 복원 |
| 5 | **1.07초** | 10000001 | **10000002** | **새 id 발급** |

**역설**: 부재가 가장 짧은 1.07초에서만 새 id가 발급됐고, 6초·11.5초 부재는 동일 id로 복원됐다.
부재 시간이 지배 변수라면 정반대여야 한다.

**해석(추정 — 좌표 미검증)**: 지배 변수는 부재 시간이 아니라 **재진입 위치**일 가능성이 높다.
칼만 예측 지점에서 멀리 떨어진 곳으로 들어오면 IoU 게이팅이 실패해 기존 트랙과 매칭되지 않고
새 트랙이 스폰된다. ★이 추정은 **재진입 좌표를 기록·대조하지 않았으므로 검증되지 않았다.**
검증하려면 부재 전 이탈 위치와 재진입 위치의 거리를 함께 로깅해야 한다.

## 3. 6c — 가림 (PM-2 설계 입력 데이터)

| 가림# | **카운트 0 지속** | 직전 id | 복귀 id | 판정 |
|---|---|---|---|---|
| 1 | **7.49초** | 10000002 | 10000002 | 동일 id 복원 |
| 2 | 0.43초(1배치) | 10000002 | 10000002 | 동일 id 복원 |

**카운트 0 총 시간 7.92초 / 기록 89.6초 = 8.8%**

두 가지가 동시에 확인됐고, 이 조합이 PM-2 설계의 핵심 근거다:

1. **가림 동안 인원 카운트는 실제로 0으로 떨어진다** — 가려진 시간만큼 그대로 유지된다.
   ByteTrack 이 검출에 충실해진 대가로, iou 코스팅이 우연히 제공하던 완충이 사라졌다.
2. **그러나 트랙 자체는 살아 있다** — 재등장 시 동일 id 로 복원됐다(track buffer 동작).

→ **추적은 사람을 붙들고 있는데 카운트만 떨어진다.** 즉 카운트를 트래커 상태에서 유도하면
가림 구간을 메울 수 있다(PM-2 1안). 실측 기준점은 **가림 최장 7.49초**다.
