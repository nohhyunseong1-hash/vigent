# [M2] 야간·저조도 person 검출 — 1차 측정 (2026-08-20 밤)

> 목적: "야간은 미측정"을 **"야간은 이 조건에서 이 정도"** 로 바꾼다.
>
> 도구: `benchmarks/m2_night_person.py` · 원자료: `benchmarks/m2_night_result.json`
> 재현: `python benchmarks/m2_night_person.py --label <조건> --person|--no-person --seconds 120`
>
> 실카메라(Tapo RTSP)를 **읽기만** 했다 — 실서비스 파이프라인이 실제로 내놓는 검출을 그대로 집계.

## 0. 이번에 잰 것 / 못 잰 것

| | 상태 |
|---|---|
| 야간 **무인** 조건(사람 없음) → 오탐률·신뢰도·화면밝기 | ✅ **실측 완료**(아래) |
| 야간 **유인** 조건(사람 있음) → **재현율** | ⏸ **미측정** — 화면 안에 사람이 있어야 정답이 성립한다(사람 필요, §4) |
| 소등 조건 | ⏸ **미측정** — 조명 조작이 필요(사람 필요) |

조도계가 없어 **화면 밝기 통계(0~255)** 를 대체 지표로 남겼다 — 조건 간 비교는 가능하다.

## 1. 실측 — 야간 무인(조명 켜짐)

| 항목 | 값 |
|---|---|
| 조건 | 2026-08-20 21:5x, 실내 **야간·방 조명 켜짐**, 사람 없음(프레임 육안 확인) |
| 관찰 | 120초 · 검출 회차 **110회** |
| **person 오탐 회차** | **95 / 110 = 86.4%** |
| 오탐 신뢰도 | p50 **0.445** · 평균 0.448 · 범위 **0.357 ~ 0.666** (n=95) |
| 화면 밝기 | 평균 **123.2 / 255** · 어두운 픽셀(<40) 비율 **0.07** |

### 🔴 원인 — 어둠이 아니라 **화각**이다

오탐 박스가 매번 거의 같은 자리다: `[0.20, 0.76, 0.98, 1.00]` — **화면 하단 전체를 덮는
가로 띠**. 스냅샷을 눈으로 확인하니 그 자리에는 **책상 아래 검은 장비(붉은 띠가 있는
어두운 물체)** 가 있고 **사람은 없다.**

즉 이 오탐은 저조도 때문이 아니다. 화면 밝기 평균이 123/255 로 어둡지 않고, 어두운 픽셀
비율도 7% 에 불과하다. **카메라가 벽·책상 밑을 향하고 있어 큰 어두운 물체가 화면 하단을
채우는 화각**이 원인이다.

- 오탐 conf 0.357~0.666 은 **운용 임계(person 0.40)를 대부분 넘는다** → 검출로 채택된다.
- 다만 **추적 활성 임계(0.70)에는 못 미친다** → 추적은 붙지 않는다.

### 🔴 이것이 M3(24시간 오탐)와 같은 원인이다

[M3](m3_alert_rate_2026-08-20.md)에서 24시간 무인 가동 중 **immobility 221건**이 발생했는데,
"움직이지 않는 person" = 정지 물체를 사람으로 오검출한 결과와 정확히 일치한다.
**정지한 오탐 박스는 자동으로 무동작(쓰러짐 의심) 경보가 된다** — 오탐 하나가 경보 하나를
낳는 게 아니라 **지속적으로 낳는다**.

## 2. 이 수치를 어떻게 읽어야 하나 (규칙7)

**이 86.4%를 제품 성능으로 인용하면 안 된다.** 이것은 "작업 현장이 아닌, 잘못 겨눠진
카메라"의 값이다. 정확한 해석은 다음과 같다.

| 읽으면 안 되는 방식 | 정확한 해석 |
|---|---|
| ~~"야간 오탐률 86%"~~ | "이 화각·이 장면에서 정지 물체 1개가 지속적으로 person 으로 잡힌다" |
| ~~"야간에는 못 쓴다"~~ | **야간 성능은 아직 판단할 근거가 없다** — 사람 있는 조건을 못 쟀다 |

★**오히려 이 측정이 확인해준 것**: `docs/camera_requirements.md` 의 화각 요건이
빈말이 아니라는 것. 카메라를 잘못 겨누면 **사람이 없어도 경보가 계속 울린다.**

## 3. 한계

| 항목 | 내용 |
|---|---|
| 재현율 미측정 | 사람이 화면에 있어야 정답이 성립 — 이번 구간은 사람 없음 조건뿐 |
| 소등 조건 미측정 | 조명 조작 필요 |
| 조도 미측정 | 조도계 없음 — 화면 밝기(0~255)로 대체. 절대 조도(lux)와 환산 불가 |
| 1개 장면·1개 화각 | 다른 화각·다른 현장에서 같은 결과가 나온다는 근거 없음 |
| 1회 측정 | 120초 1회. 분산 미확인 |
| 주간 대조 없음 | 같은 화각의 주간 값이 없어 "주간 대비" 비교 불가(카메라가 이동돼 과거 주간 데이터와 장면이 다르다) |

## 4. 남은 측정 절차 (사람 필요 — 약 8분)

> 카메라를 **사람이 서 있을 공간이 보이도록** 돌려놓고, 아래 3구간을 순서대로 실행한다.
> 각 구간 동안 **화면 안에 계속 머물러야** 정답이 성립한다(잠깐 나갔다 오면 그 회차는 놓침으로 집계됨).

```
# ① 야간 · 조명 켜짐 · 사람 있음 (2분간 화면 안에 머무를 것)
python benchmarks/m2_night_person.py --label "야간_조명on_유인" --person --seconds 120

# ② 야간 · 소등 · 사람 있음 (불 끄고 2분)
python benchmarks/m2_night_person.py --label "야간_소등_유인" --person --seconds 120

# ③ 야간 · 소등 · 사람 없음 (불 끈 채로 화면 밖에서 2분)
python benchmarks/m2_night_person.py --label "야간_소등_무인" --no-person --seconds 120
```

세 구간이 끝나면 `benchmarks/m2_night_result.json` 에 누적되고, 아래 표가 채워진다.

| 조건 | 화면밝기 | 재현율 | conf p50 | 오탐률 |
|---|---|---|---|---|
| 야간·조명on·무인 | **123.2** | — | — | **86.4%** ✅ 측정됨 |
| 야간·조명on·유인 | — | ⏸ | ⏸ | — |
| 야간·소등·유인 | — | ⏸ | ⏸ | — |
| 야간·소등·무인 | — | — | — | ⏸ |

★같은 화각의 **주간 대조**가 필요하면 내일 낮에 ①을 한 번 더 돌리면 된다
(`--label "주간_유인"`). 그래야 "주간 대비 야간" 을 말할 수 있다.

---

## 4-1. ★[2026-08-22 보강] 화각을 바꿨다면 **무인 재측정이 먼저다**

1차 측정의 결론은 "야간이 문제가 아니라 **화각**이 문제"였다(§1). 그러므로 화각을 돌린
뒤에는 **①~③ 전에 무인 오탐을 다시 재야 한다** — 그러지 않으면 재현율이 좋게 나와도
"오탐 86.4%가 해결됐는지"를 말할 수 없고, 1차 수치와 비교할 기준선도 사라진다.

```
# ⓪ 새 화각 · 야간 · 조명 켜짐 · 사람 없음  ← 1차(86.4%)와 직접 비교되는 기준선
python benchmarks/m2_night_person.py --label "야간_조명on_무인_새화각" --no-person --seconds 120
```

**⓪를 먼저 돌린 뒤** ①②③을 이어서 한다. 총 4구간 · 약 10분(구간 사이 이동 시간 별도).

### 실행 전 확인 (오늘 겪은 것)

- [ ] **카메라 id 가 `test` 인가** — 스크립트 기본값이 `--cid test` 다. 다른 이름으로
      등록했다면 `--cid <실제id>` 를 붙인다. **없는 id 를 주면 조용히 0회차로 끝난다.**
- [ ] **`/health` 에 유령 카메라가 없는가** — 삭제된 카메라가 `stopped` 로 남아 있으면
      집계가 오염된다(2026-08-21 capacity_probe 를 무효로 만든 원인). 서버 수정으로
      해소됐으나, 구버전이 떠 있으면 재시작 후 시작할 것.
- [ ] **구간 내내 화면 안에 머문다** — 잠깐 나가면 그 회차가 '놓침'으로 집계돼 재현율이
      실제보다 낮게 나온다. 반대로 ⓪③ 구간엔 **절대 들어가지 않는다**.
- [ ] 각 구간 사이에 **스냅샷을 한 장 저장**해 둔다 — 나중에 "그때 화면이 어땠는지"를
      숫자만으로는 복원할 수 없다(1차에서 오탐 원인을 찾은 것이 스냅샷 육안 확인이었다).

### 결과를 읽는 법 (★규칙7 — 이상하면 먼저 의심한다)

| 나온 값 | 먼저 의심할 것 |
|---|---|
| 재현율이 **100%** | 사람이 아니라 **정지 물체를 계속 잡고 있는** 것일 수 있다(1차 오탐과 동일). 스냅샷으로 박스 위치를 확인한다 |
| 재현율이 **0%** | `--cid` 가 틀렸거나 카메라가 `stopped` 다. `/health` 를 먼저 본다 |
| 회차 수가 예상보다 **훨씬 적다** | 검출이 멈췄거나(stale_detect) fps 설정이 낮다 |
| 소등 조건인데 밝기가 1차와 **비슷** | 불이 실제로 안 꺼졌거나 IR 야간모드가 켜진 것이다 — 조건이 성립하지 않았으므로 다시 잰다 |
