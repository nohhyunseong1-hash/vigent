# [P-2] person 이중 신호 앙상블 — dev셋 측정 결과 (2026-08-10)

> **dev 74장으로만 채점**(`data/field_eval/dev_test_split.json`, [P-0] 원칙). test는 안 건드림.
> 측정=배포 조건과 동일(imgsz=960, 운용 임계 person 0.40/ppe 0.35, `config/tuning.yaml`).
> 도구: `benchmarks/p2_person_ensemble.py`.

## 1단계 — 겹침/차집합 (dev, GT person 157건)

| | 건수 | 비율 |
|---|---|---|
| 둘 다 잡음(both) | 62 | 39.5% |
| A(person 슬롯)만 잡음 | 25 | 15.9% |
| B(ppe 슬롯 Person)만 잡음 | **24** | **15.3%** |
| 둘 다 놓침(neither) | 46 | 29.3% |

| | 재현율 | 정밀도 |
|---|---|---|
| A(person 슬롯) 단독 | 55.4% | 89.7% |
| B(ppe 슬롯 Person) 단독 | 54.8% | 82.7% |

**겹침이 "거의 전부"가 아니다(39.5%뿐)** — B만 잡는 15.3%가 실재하는 잠재 이득이라 2단계로 진행.

## 2단계 — OR + NMS(IoU≥0.5) 앙상블

| | A(현재) | 앙상블 | 변화 |
|---|---|---|---|
| 재현율 | 55.4% | **70.7%** | **+15.3%p** |
| 정밀도 | 89.7% | 79.9% | −9.8%p |
| F1 | 68.5% | **75.0%** | **+6.5%p** |
| TP / FP | 87 / 10 | 111 / 28 | +24 TP / +18 FP |

**교환비: 오탐 1건당 정탐 1.33건 회수(18 FP로 24 TP 획득, FP/TP=0.75)** — person 임계 스윕에서
기각됐던 교환비(정답 1건당 오탐 1.6~2.9건, 그 반대 방향으로 훨씬 나쁨)와 정반대로 **유리한 거래**다.
F1도 순증(+6.5%p, 임계 스윕의 +0.8%p보다 8배 큰 개선).

## 3단계 — 정밀도 하락 vs 재현율 상승 판정 (규칙6)

**재현율 상승(+15.3%p)이 정밀도 하락(−9.8%p)보다 크다 → 기각 기준에 해당하지 않음. 채택 권고.**

## 4단계 — 지연 영향 (★배포 구조상 대부분 무료)

| 신호 | median 지연 |
|---|---|
| A(person 슬롯) | 14.2ms |
| B(ppe 슬롯) | 13.0ms |
| 단순 합산(순차 실행 가정) | 27.3ms |

**단, 이 "27.3ms 추가"는 실제 배포 경로 대부분에 해당하지 않는다** — `vigent-core/worker.py` 확인 결과:

- **`do_full`(풀세트, 2fps, PPE 판정용)는 이미 `detectors=["person","ppe",...]`를 함께 돌린다**
  (`worker.py:642`, `routers/ppe.py:61`, `routers/safety_core.py:421`도 동일). 이 경로에서 앙상블은
  **이미 계산된 두 검출 결과를 합치는 것뿐이라 추가 추론 비용이 사실상 0**이다.
- **`focus_active`(person 전용 고속 5fps, `worker.py:638`)는 표시 전용 트래킹을 위해 의도적으로
  person 슬롯만 돌리는 저비용 경로**다(`worker.py:624-627` 주석: "focus 예산 ≈ 2×85[풀세트] +
  5×27[person] = 305ms/s"로 세밀하게 예산을 짜둠). 여기에 앙상블을 적용하면 이 예산 설계가
  깨진다 — **이 경로는 건드리지 않는 게 맞다**(어차피 표시용이라 PPE 판정 정확도와 무관).

**권고**: 앙상블은 `do_full` 풀세트 경로(PPE 판정에 실제로 쓰이는 person 검출)에만 적용한다.
그러면 지연 비용은 거의 0이고, `focus_active` 고속 표시 경로는 기존 그대로 둔다.

## ★구현 착수 전 재발견 — 병합 로직은 이미 존재했다

guard.py를 직접 확인한 결과, `_nms`(전체 검출 대상 IoU 중복제거)와 `_merge_cross_source_person`
(추적 이후 교차소스 person 중복만 병합, 안 B)이 **이미 코드에 있었다.** `detectors=["person","ppe"]`
를 함께 부르면(실제로 `do_full`·`routers/ppe.py`·`routers/safety_core.py`가 이미 그렇게 부른다)
ppe 슬롯의 Person 클래스도 무조건 같은 파이프라인에 섞여 들어가고, 겹치는 중복만 정리될 뿐 한쪽만
잡은 고유 검출은 원래도 그대로 통과했다. 검증: `detect_isolated(guard, img, detectors=["person",
"ppe"])`를 dev에 직접 돌려보니 **재현율 68.2% / 정밀도 81.7%** — 위에서 수작업으로 계산한
OR+NMS 앙상블(70.7%/79.9%)과 거의 같았다(실제 파이프라인의 dedup 임계가 조금 더 보수적이라 그만큼
차이).

즉 **"이중 신호 앙상블"은 이미 실제 운영 코드에 존재하던 동작**이었고, `field_eval_results.md`의
56.7% 수치가 낮게 나온 건 `run_eval.py`가 `field_eval_person` 평가에서 `detectors=["person"]`만
단일 호출했기 때문(모델 성능을 슬롯별로 순수하게 재려는 의도적 설계) — **버그가 아니라 측정
방법론의 선택**이었다. 그래서 "구현"은 새 병합 알고리즘을 만드는 게 아니라, **이미 있는 동작에
이름(`PERSON_ENSEMBLE`)을 붙이고 끌 수 있게 만드는 것**으로 범위가 좁혀졌다.

## 구현 (`vigent-core/agents/guard.py`)

- `GuardAgent.PERSON_ENSEMBLE`(기본 `True` — 오늘까지의 실제 동작 그대로, 회귀 없음).
  `config/tuning.yaml` `detect.person_ensemble`로 조정.
- `_drop_ppe_origin_person(dets)`(신규 free function): `PERSON_ENSEMBLE=False`일 때만 호출 —
  `_cross_validate_ppe`(PPE 항목이 사람과 결부됐는지 판정) **이후, `_track` 이전**에 ppe 슬롯 유래
  person 후보를 제거한다. 이 순서가 중요한 이유 둘:
  1. **추적 이전에 걸러야** ppe 유래 박스가 트랙 상태에 반영된 뒤 사라지는 오염을 막는다.
  2. **cross_validate_ppe는 플래그와 무관하게 항상 전체 person 컨텍스트로 판단** — "이 PPE
     항목 근처에 누군가 있는가"는 person 재현율 실험과 별개 관심사라 그대로 둔다. 부작용:
     `PERSON_ENSEMBLE=False`여도 ppe 슬롯 person 근처의 NO-Hardhat 등은 그대로 남을 수 있다
     (의도된 동작, `tests/test_person_ensemble.py`에 명시적으로 회귀 테스트함).

## ★채택 전 확인1 — 하류 오탐(가짜 person → 가짜 "미착용" 경보) 영향 (`benchmarks/p2_downstream_fp_check.py`)

dev 74장, `PERSON_ENSEMBLE=True`(채택 시 기본값) 기준 미착용(NO-Hardhat/NO-Safety-Vest/NO-Mask)
전수 확인:

| | 건수 |
|---|---|
| 미착용 총 검출 | 116 |
| 그중 오탐(FP) | 12 |
| — 근처에 진짜(GT매칭) person 있음(오탐이지만 유령person 탓 아님) | 4 |
| — ★근처 person 전부 가짜(완전 유령 미착용 경보) | **8** |

**8건 전부 `KakaoTalk_20260807_000633827` 영상 1개에 집중**됐다(이미 `field_eval_gt_summary.md`·
`perf_improvement_plan.md`에서 "오탐이 몰린 영상"으로 별도 기록된 그 영상 — 89장 검수에서도
유일하게 삭제(19)가 추가(2)를 압도한 곳). 전체 미착용 검출 116건 대비 6.9%, 74개 프레임 중
소수 프레임에 국한.

**판단**: 빈도가 낮고(6.9%) 특정 1개 영상에 국한돼 있어(전 영상에 걸친 체계적 문제가 아님)
"잦다"고 보지 않았다 — **conf 가중·ppe-Person 단독 임계 상향 같은 변형은 시도하지 않았다.**
대신 `000633827` 영상은 이미 `docs/perf_improvement_plan.md` P-3-3(정답지 교차검증)에 "재검토"
항목으로 올라가 있어, 그 재검토 때 이 유령 경보도 함께 살펴보는 것으로 충분하다고 판단.
(이견 있으면 재검토 가능 — 규칙7: 판단 근거를 여기 남김.)

## ★채택 전 확인2 — 추적/containment/dedup 회귀 (`tests/test_person_ensemble.py`, 4개 신규 테스트)

실제 모델 없이 `GuardAgent.__new__()` + 가짜 어댑터로 `detect()` 전체 경로를 실행해 확인:

1. **앙상블 on**: 교차소스 중복(person 슬롯+ppe 슬롯이 거의 같은 위치를 잡음)은 1개로 병합(높은
   conf 유지), 한쪽만 잡은 고유 검출은 보존, 근처 PPE 항목도 정상 결부.
2. **앙상블 off**: ppe 유래 person만 제거되고 person 슬롯 검출은 그대로 유지. PPE 항목 결부는
   플래그와 무관(위 "부작용" 문단대로 의도된 동작임을 명시적으로 검증).
3. **추적 안정성**: 동일 장면을 5프레임 연속 넣었을 때 tid가 프레임마다 흔들리지 않음(on/off 둘 다).
4. **containment 억제**: 서로 다른 detector 출처의 person 박스(큰 박스 안 작은 박스, conf 낮은 쪽)도
   기존 포함비 억제 로직이 정상 처리.

4개 전부 통과. 기존 108개 테스트도 회귀 없음(전체 112개 통과).

## 결론

**채택 완료(2026-08-10 구현).** dev 기준 person 재현율 55.4%→70.7%(+15.3%p), F1 68.5%→75.0%
(+6.5%p), 배포 구조상 추가 지연 비용은 PPE 판정에 실제로 쓰이는 경로에서 거의 0(이미 그렇게 동작
중이었음). 하류 오탐 확인 결과 유령 미착용 경보는 낮은 빈도(6.9%)로 이미 알려진 특정 영상에 국한 —
추가 변형 없이 채택. 추적·containment 회귀 없음(신규 테스트 4개 + 기존 108개 전부 통과).
person 재현율은 P-3-2(사람 크롭 2단계 PPE)의 상한이기도 해서, 이 개선은 이후 실험에도 파급 효과가
있다.

**여전히 안 한 것**:
- **test 35장으로는 아직 재지 않았다** — [P-0] 원칙대로 전 실험(P-3까지) 종료 후 단 1회만 연다.
- NMS IoU 임계(0.5)·병합 방식(단순 OR+NMS, 실제로는 기존 `_merge_cross_source_person`의 0.45)은
  기존 값 그대로다. 클래스 신뢰도 가중 등 다른 병합 방식은 시도하지 않았다(확인1에서 필요성이
  낮다고 판단).
