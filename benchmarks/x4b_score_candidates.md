## 학습 개요

`benchmarks/x4_train_full.py`: 기존 `ppe_rfdetr_v1.pth`에서 이어 파인튜닝, 데이터셋
`data/datasets/css_safety_aug`(person random erasing + copy-paste 가림 + NO-Hardhat/Hardhat
축소 증강, train 4408장), 해상도 384, epochs=50 상한 + early_stopping(patience=8, css valid
split의 `val/mAP_50_95` 모니터). **best epoch 8**(css valid mAP@50:95 0.4977→0.5009,
patience 8 소진으로 조기종료, 총 52.2분·3132.6초, 16 epoch 실행). 3개 체크포인트 저장:
`checkpoint_best_ema.pth`·`checkpoint_best_regular.pth`·`checkpoint_best_total.pth`(이번
런에서 total=ema와 수치 동일 — 학습 로그가 "Best total checkpoint saved **from EMA**"라고
명시, ema 점수 0.5009가 regular 0.4977보다 높아 total이 ema를 그대로 채택했기 때문).

크다 — 규칙6에 따라 채택하지 않는다.**

## 원인 추정(★미검증, 규칙7)

학습 중 css v27 자체 valid split(114장, 우리 데이터와 무관)에서는 mAP@50:95가
0.4734→0.5009로 실제로 개선됐다(학습 로그 실측) — 즉 학습 자체는 "의도한 대로" 진행됐다.
그런데 우리 dev 74장(실제 현장 CCTV 프레임)에서는 거의 전 지표가 나빠졌다. 이는 **css v27
valid에서의 개선이 우리 현장 도메인으로 전이되지 않았다**는 뜻으로 읽힌다. 가능한 원인(전부
미검증 가설):
- 증강(특히 copy-paste 가림·축소)이 css v27 자체 분포에는 맞지만 실제 현장 영상과는 다른
  방식으로 이미지를 바꿔, 모델이 "css v27 스타일의 가림"에는 나아지고 실제 가림에는 도움이
  안 됐을 가능성.
- 이어하는 파인튜닝(continued fine-tuning)이 원 체크포인트가 이미 갖고 있던 현장 도메인
  적응을 일부 덮어썼을 가능성(catastrophic forgetting류) — patience=8로도 못 막을 만큼
  처음 몇 epoch 안에 이미 벗어났을 수 있다.
- 데이터셋 자체가 이미 원 체크포인트의 학습 소스(css v27)와 같아서, 재학습이 사실상 "같은
  데이터를 증강만 바꿔 더 돌리는 것"이었고, 이번 증강 구성이 이 체크포인트·이 데이터
  조합에는 맞지 않았을 가능성.

이 중 어느 것이 맞는지는 이번 실험만으로는 알 수 없다 — 추가 검증 없이는 "모른다"가 정직한
답이다.

## 결론

신규 체크포인트 3종 전부 배포하지 않는다. `vigent-core/weights/`·`MANIFEST.md` 미변경(현행
`ppe_rfdetr_v1.pth` 유지). 후속 시도 시 참고할 점: css valid 성능 개선이 dev 성능 개선을
보장하지 않는다는 것이 이번 실험의 핵심 실측 결과 — 앞으로는 학습 중간에도 (가능하면) dev
기준 체크포인트를 확인하는 절차가 필요할 수 있다(제안, 미결정).
