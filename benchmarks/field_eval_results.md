## 2. ★순환 제거 — 모델의 진짜 사각지대

정답지가 이 모델의 초안에서 출발했으므로, 정답 박스를 출처별로 갈라 따로 센다.

| 출처 | 사람 | PPE |
|---|---|---|
| **모델 유래**(사람이 유지) | 72/90 = 80.0% | 176/180 = 97.8% |
| **사람 추가**(모델이 못 봤던 자리) | **42/111 = 37.8%** | **29/144 = 20.1%** |

**핵심: 모델은 자기가 원래 찾았던 것은 다시 찾지만, 원래 놓쳤던 것은 5개 중 1개(PPE)
~ 5개 중 2개(사람)밖에 못 찾는다.** 이것이 순환에 오염되지 않은 유일한 성능 지표다.

> **왜 mAP 를 쓰지 않았나**: `field_eval_ppe` 의 mAP@50 과 mAP@50:95 가 6개 클래스 전부
> 소수점까지 동일하게 나왔다(70.84%). 사람이 손대지 않은 박스는 모델 예측과 좌표가 같아
> IoU=1.0 이 되기 때문이다(guard `_track_iou` 는 격리 프레임에서 좌표를 변형하지 않음 — 코드 확인).
> **`field_eval_*` 의 mAP@50:95 는 인용하지 말 것.**

## 4. 측정의 신뢰 범위 (규칙7)

- **출처 판정 정확도**: 89장 구간은 초안 파일과 **직접 대조**해 갈랐다(정확). 파일럿 20장은
  초안 원본이 보존돼 있지 않아 "예측과 IoU≥0.999" 휴리스틱을 썼다. 89장 구간에서 두 방법의
  일치율은 **PPE 98.0% / 사람 68.0%** — 즉 **사람 쪽 파일럿 20장분 출처 판정은 오차가 있다.**
  사람의 37.8%는 대략치로 보고, PPE 의 20.1%가 상대적으로 신뢰도가 높다.
- **정답지 자체의 오차는 측정되지 않았다.** 1인 1회 검수이고 교차검증을 하지 않았다.
  위 수치의 상한은 정답지 품질이 정한다.
- **★정정(2026-08-10, [Q-4], 규칙7)**: 아래 원문은 "초안 imgsz=640 vs 측정 imgsz=960 차이가
  원인일 수 있다"고 적었으나 **실제로는 둘 다 384였다** — RF-DETR 어댑터가 `imgsz`를 받고 실제
  모델 호출에 안 쓰던 dead parameter 버그 때문에([Q-3]에서 수정, `benchmarks/
  p3_1_resolution_ab_BLOCKED.md`) 이 문서의 148ms 측정을 포함해 이 저장소의 모든 RF-DETR
  추론이 그동안 384로 돌았다. **즉 이 문단이 지목한 원인(해상도 차이)은 존재하지 않았다** — 사람
  쪽 출처 판정 불일치(68%)의 진짜 원인은 여전히 불명(모른다, 원인이 하나 배제됐을 뿐).

  (원문, 이제 부정확함): ~~정답지 생성과 측정의 추론 설정이 다르다. 초안은 imgsz=640·conf=0.10,

- **지연 148ms 는 CPU 전용 환경 값**이다. Docker/WSL2 종료 여부에 따라 오염될 수 있어,
  이 값은 `docs/benchmark_measurement_hygiene.md` 절차 준수 시에만 유효하다.

## 5. 이 결과가 가리키는 것

1. **개선 우선순위는 재현율, 그중에서도 `NO-Hardhat`.** 정밀도(≈90%)는 이미 쓸 만하다.
2. **임계 하향은 답이 아닐 수 있다.** 놓친 객체 대부분은 conf 0.10 초안에도 안 잡혔던 것들이다
   (사람이 새로 그린 177건). 임계를 낮춰도 안 보이는 객체는 여전히 안 보인다 — 학습 데이터
   보강이나 모델 교체가 필요한 영역이다.
3. **영상별 편차가 크다**(`benchmarks/field_eval_gt_summary.md` §3): `000552920` 는 거의 다 놓치고
   `000633827` 은 오탐이 몰린다. 단일 임계로 전 현장을 덮는 접근의 한계를 시사한다.
4. **조끼는 이 데이터로 평가 불가**(양성 2건). 별도 데이터 확보 없이는 조끼 관련 주장 금지.
