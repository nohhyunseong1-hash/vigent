`benchmarks/r2_000633827_review.py`(2026-08-10)가 만든 dev 14프레임 GT|검출 나란히
미리보기(`data/field_eval/review_000633827/`, gitignore 대상)를 사용자가 재검토했다.

오검출되는 패턴을 근거로 승인.

**★이어서 진행한 정량화(§2)에서 이 가설이 부분적으로 기각됐다** — 아래 근거로, "설비

## 3. 결론 — 단순 마스킹은 이 카메라에 적합하지 않다(재검토 필요)

1차 판정(설비 영역 마스킹)의 전제 — "오탐은 항상 사람 없는 설비 자리에서만 난다" — 는
정량화 결과 성립하지 않는다:
- 오탐 위치 자체가 프레임 전역에 산발적이라 "설비 영역"을 하나의 작은 사각형으로 특정하기
  어렵다(§2.1).
- 좁혀서 마스킹하려 해도, 오탐이 자주 나는 우측~우상단 영역은 실제 작업자가 서는 자리와
  겹친다(§2.2) — 그 영역을 마스킹하면 진짜 위험(9000·11000·12000ms의 실제 NO-Hardhat
  가능성)을 놓칠 위험이 생긴다(규칙6 — 저하 방향 변경은 승인 없이 진행하지 않는다).

**따라서 000633827 카메라 자체에 대해서는 마스킹을 적용하지 않을 것을 권장한다.**
대신 이 영상의 근본 문제는 "카메라가 설비에 너무 가깝게(근접샷) 붙어 있어 배경(설비)과
전경(사람)이 화면상 거의 분리되지 않는다"는 **설치 각도/화각 문제**로 보인다(추정,
미검증) — `docs/camera_requirements.md`(카메라 설치 각도 요구사항 문서, [X-2])에 이
사례를 "근접 설비 밀착 촬영 지양" 근거로 추가하는 게 마스킹보다 근본적인 해결책일 수
있다.

## 4. 마스크 존 — 일반 기능으로는 설계안 제시(적용 여부는 별도 승인)

000633827에는 적용을 보류하지만, "카메라 화면의 특정 영역을 검출 대상에서 제외"하는
기능 자체는 오탐이 실제로 한 자리에 고정되는(공간 분리가 되는) 다른 현장에는 유효할 수
있어 범용 기능으로 설계안만 남긴다 — **구현은 하지 않았다, 승인 대기.**

### 4.1 메커니즘

`config/danger_zone.json`/`machine_zone.json`과 같은 패턴(정규화 폴리곤, ray-casting) —
새 `mask_zones.json`(카메라별)을 두고, `RfdetrDetector.detect()`(또는 그 상위
`finalize_box` 직후)에서 박스 중심점(또는 IoU 기준 포함비)이 마스크 존 폴리곤 안에 들면
그 검출을 **버린다**(이벤트로도, 화면 표시로도 안 올라감).

```json
// config/mask_zones.json (신설, danger_zone.json과 동일 포맷 참고)
{
  "000633827": {
    "points": [[x1,y1],[x2,y2], ...],   // 정규화 0~1 폴리곤
    "classes": ["NO-Hardhat","NO-Mask","Mask","Safety-Vest","NO-Safety-Vest"],
    // person 은 절대 마스킹 대상에 넣지 않는다(아래 §4.2 안전장치와 이중 방어)
    "reason": "고정 설비 오탐(2026-08-12 R-2 재검토, benchmarks/r2_mask_zone_review.md)",
    "created": "2026-08-12"
  }
}
```

### 4.2 안전장치(규칙6 — 반드시 지킬 것)

- **person 클래스는 절대 마스킹하지 않는다** — PPE 항목만 마스킹 대상으로 허용. 사람
  자체를 지우면 "이 구역엔 아무도 없다"는 최악의 착시가 생긴다(진짜 사람이 있어도
  안 보임).
- **마스크 존은 검출 자체가 아니라 "특정 클래스의 이 위치 결과만" 버리는 것** — 같은
  프레임의 다른 위치·다른 클래스 검출에는 영향 없음(가산식 설계 원칙 유지).
- **적용 전 필수 확인**: 그 구역에 실제 작업자가 서는지(GT나 현장 확인으로) 먼저 검증 —
  이번 000633827처럼 오탐 자리와 작업 자리가 겹치면 적용 보류.
- **감사 로그**: 마스킹으로 버려진 검출 수를 카메라별로 집계해 어딘가(가능하면
  `/health` 또는 별도 엔드포인트)에 노출 — "몇 건이 조용히 버려지고 있는지" 안 보이면
  나중에 실제 위험까지 같이 지워지고 있어도 아무도 모른다.
