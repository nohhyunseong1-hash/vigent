## 항목별 상세

### 항목 1. 라이선스 청정성 — **A**
- **확인 명령·결과**:
  - `grep -rn "import ultralytics" vigent-core/` → 5건, **전부 학습 스크립트(`ml/train_*.py`)·구 boda 분류기**. 라이브(main/worker/guard) import **0건**.
  - 런타임 실증: 테마 빌드 + 4슬롯 `guard.detect` 실행 후 `sys.modules`에 `ultralytics` **부재(False)**.
  - `requirements.txt`(배포)에 ultralytics **없음**, `requirements-eval.txt`(측정 전용)에만 잔존.
- **근거**: AGPL(카피레프트) 패키지 ultralytics가 **배포물·실행 경로에 전혀 로드되지 않음**. 4개 탐지 슬롯 전부 RF-DETR(Apache-2.0)·RTMPose(Apache/MIT)로 이관 완료(태그 `v1.0-copyleft-zero`).
- **남은 작업**: 학습 스크립트(`ml/train_*.py`)의 ultralytics는 배포와 무관하나, 완전 정리를 원하면 제거 가능(선택). `detectors/yolo_adapter.py`는 롤백 안전망으로 의도적 존치(지연 import·배포 미포함).

### 항목 2. 탐지 모델 상태 — **B**
- **가중치 파일**(전부 존재, `vigent-core/weights/`):
  - `ppe_rfdetr_v1.pth` · `fire_smoke_rfdetr_v1_e17.pth` · `forklift_rfdetr_v1.pth` (각 ~120MB) · person은 RF-DETR COCO 사전학습(별도 파일 불요).
- **평가 수치**(`benchmarks/EVAL.md`, 실측 기록):
  | 클래스 | 배포 운용점 mAP@50 | 비고 |
  |---|---|---|
  | person | **92.94%** | 우수. 서버 배포=측정 Δ0.00 검증(F-8) |
  | PPE(보호구) | **71.46%** | css_safety in-domain. 미착용류 recall 80~97 |
  | fire_smoke | **69.64%**(D-Fire box 80.13%) | D-Fire in-domain, 게이트 통과 |
  | forklift | **8.5%** | ⚠️ 매우 낮음(학습 192장 과소) |
- **KISA F1 ≥ 90% 대비 갭**: **F1 직접 측정 기록 없음**(mAP 위주). mAP 기준으로도 person만 90%대 근접, PPE·fire는 70%대, **forklift는 심각 미달(8.5%)**. KISA F1 인증 목표라면 **별도 F1 측정 + 현장 데이터 재학습 필요**.
- **공통 한계(정직)**: 4종 모두 **in-domain**(학습셋=평가셋 출처) 수치. **현장 영상 일반화 미검증**(FINDINGS T10c-V 대기). 실내 사무실에서 PPE 오탐 확인됨(FINDINGS **F-9**, 도메인 갭).
- **남은 작업**: ① 현장 클립으로 재검증(T10c-V) ② forklift 데이터 보강·재학습 ③ F1 지표 측정.

### 항목 6. 에이전트 계층 (L2) — **B**
- **에이전트 파일**(`vigent-core/agents/`): Dispatcher·Guard·Analyst·Scribe·Coach·Copilot **6종 + safety_manager·base**(총 9파일) 존재.
- **LangGraph**: **미사용** — 요구 명세는 "LangGraph 6-agent"이나 실제는 **자체 에이전트 구조**(base.py 상속). 기능적으로 6-agent 역할은 구현됨, 프레임워크만 다름.
- **LLM(폐쇄망 대응)**: `llm_provider.py` — `VIGENT_LLM_PROVIDER=ollama`(기본, **로컬·무료·키불요**) ↔ `anthropic`(Claude API, 실사업) **스위치 존재**. 폐쇄망은 ollama로 오프라인 동작.
- **판단 근거 로그**: vlog 구조화 로깅으로 남음(에이전트별). 위험성평가는 법령 조항 인용.
- **남은 작업**: 요구가 LangGraph 명시라면 마이그레이션 검토(현 자체구조로 충분하면 명세 조정). 에이전트 판단 추적 로그 표준화.

### 항목 7. 안정성 / 자동 복구 — **C**

- **카메라 재연결**: go2rtc 연결 실패 → **웹캠 자동 폴백**(index_local.html). 스트림 끊김 대응 존재.
- **전역 예외 처리**: `@app.exception_handler` **0건** — FastAPI 전역 예외 핸들러 **부재**. 개별 try/except는 있으나 최상위 안전망 없음.
- **24시간 연속 구동**: 검증 기록 **미발견**(soak/uptime 테스트 없음).
- **남은 작업**: ① 전역 예외 핸들러 추가 ② 24시간 soak 테스트 1회 ③ macOS launchd 자동재기동 실증(현재 Linux systemd 위주).

## 대표 확인용 3줄 요약

1. **지금 팔 수 있나?** — 기술 **기반은 납품 가능 수준**입니다(라이선스 깨끗, 보안·패키징·아키텍처 갖춤). 하지만 **"우리 현장에서 실제로 정확한가"를 아직 증명 못 했습니다**(공개 데이터 기준 수치뿐) → **조건부**, 지금 당장 유료 납품은 이릅니다.

2. **아니라면 며칠?** — **현장 영상만 확보되면 약 1~2주**입니다. 현장 클립으로 재검증(2~3일) + 지게차 재학습(3~5일) + F1 측정·24시간 검증(3일). 병목은 개발이 아니라 **현장 데이터 확보**입니다.

3. **가장 큰 구멍은?** — **① 현장 미검증**(모델이 실제 현장에서 되는지 미증명), **② 지게차 탐지 성능(8.5%)**, **③ 24시간 무인 안정성 미검증**. 세 가지 모두 **현장 데이터 + 며칠의 검증 작업**으로 메울 수 있고, 근본 결함(라이선스·보안)은 아닙니다.
