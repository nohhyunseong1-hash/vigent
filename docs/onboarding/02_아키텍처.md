## 전체 그림


## 각 단계가 왜 필요한가 · 없으면 무엇이 깨지는가

| 단계 | 왜 있나 | 없으면 |
|---|---|---|
| ① 캡처(프레임 버리기) | RTSP는 실시간이라 밀리면 지연이 누적된다 | 화면이 점점 과거가 된다. 경보가 늦게 울린다 |
| ② 교차검증 | 벽·의자에 PPE 오탐이 뜬다 | 사람 없는 곳에서 "미착용" 경보 |
| ③ 추적 | 같은 사람의 반복 경보를 억제하고 주체를 식별 | 프레임마다 새 사람 취급 → 알림 폭주 |
| ④ 히스테리시스 | 단일 프레임 오검출이 곧 경보가 된다 | 깜빡임 한 번에 사이렌 |
| ⑤ 디바운스 | 구역을 스치고 지나간 것도 침입이 된다 | 오경보. **실측: 1차 시도 9프레임 스침 → 미발화가 정상 동작** |
| ⑥ 백오프 | 같은 오경보가 24시간 내내 온다 | **실측: 고정 쿨다운은 221건 중 0건을 막았다** |
| ⑦ SQLite 선기록 | 네트워크가 끊기면 경보가 증발한다 | 통보 실패 = 기록 소실 |
| ⑧ 별도 스레드 | 텔레그램 응답을 판정 루프가 기다린다 | 전송 지연(최대 3.7초)만큼 화면 판정이 멈춘다 |

## ★비동기 경계와 실패 시 동작 (리뷰어가 먼저 볼 것)

| 경계 | 넘는 방식 | 실패하면 |
|---|---|---|
| 캡처 → 판정 | 최신 프레임 1장 공유(락) | 프레임 없음 → stale 카운트 → 30초 뒤 `/health` **degraded** |
| 판정 → 큐 | **SQLite INSERT(동기)** | ★디스크 풀이면 기록·통보가 **함께** 죽는다 → [F2] 수정 완료. 현재는 degraded 표시 |
| 큐 → 전송 | 스레드 C/D가 폴링 | 전송 실패 → 행이 큐에 남아 5초마다 재시도 |
| 추론 직렬화 | `DETECT_LOCK` (**RLock**) | 재진입 경로가 있어 일반 Lock이면 자기 데드락 — RLock이 필수 |

### 스레드 수명
- `alert_queue.stop()` / `alert_notify.stop()` 은 **join 한다.**
  join이 시간 내에 안 끝나면 **참조를 유지**해 다음 `start()`가 중복 스레드를 만들지 않게 막는다.
  ※이 둘은 2026-08-28 셔플 검증에서 **실제 결함으로 발견돼 고친 것**이다([07](07_개발_규칙과_그_사연.md)).

### 모델이 없거나 실패하면
- 슬롯별 **지연 로딩**. 로드 실패 시 그 슬롯만 죽고 나머지는 돈다.
- ★**"폴백 휴리스틱"은 없다.** 문서에 있던 fallback 표기는 2026-08-24에 **거짓으로 판명돼 정정**했다 —
  모델이 없으면 그 슬롯은 **아무것도 못 본다.** `/health` 가 **DEGRADED** 로 드러낸다([F31]).

## 설정으로 갈리는 것

```
config/tuning.yaml            전역 기본값(임계·쿨다운·반경)
themes/safety/vision.yaml     모델·백엔드 선언
deploy/academy/*.yaml         ★현장 프로파일 — 전역과 다른 값만
deploy/academy/profile_intent.yaml   ★그 차이를 "왜"와 함께 선언
```

프로파일이 전역과 다르면 `scripts/check_profile_drift.py` 가 **선언 없는 차이를 실패로 잡는다.**
(전에 키 6개가 조용히 누락돼 [F5]·[F6] 방어가 학원에서 무효화될 뻔했다)

## 아직 없는 것

| | |
|---|---|
| 다중 카메라 실전 검증 | 코드는 카메라당 스레드로 되어 있으나 **현장은 1대만 해봤다** |

| 외부 심박 | 시스템이 죽으면 아무도 모른다([F9], 미해결) |
