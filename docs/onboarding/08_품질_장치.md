> ★정직하게 쓴다. **CI는 있지만 지금 작업 브랜치에서는 돌지 않는다.**
> 커버리지는 **측정한 적이 없다.**

## 1. 게이트 5종

커밋 전에 전부 통과해야 한다(`CLAUDE.md` 코드 품질 게이트).

| # | 게이트 | 명령 | 통과 기준 | 무엇을 막나 |
|---|---|---|---|---|
| 1 | **ruff** | `ruff check vigent-core tests` | 출력 0 | 린트. ★범위가 `vigent-core`·`tests`뿐 — `benchmarks/`·`scripts/` 일부는 **기존 부채가 있어 범위 밖** |
| 2 | **mypy**(점진) | `python -m mypy` | 화이트리스트 0 에러 | 타입. ★전체가 아니라 **19파일 화이트리스트**만 |
| 3 | **테스트** | `python -m unittest discover -s tests` | **481건 OK** | 배선·상태기계·설정 안전장치 |
| 4 | **OpenAPI 차분** | `python scripts/check_openapi_diff.py` | 경로·메서드 **106 == baseline** + WS 불변 | 라우터를 쪼개다 엔드포인트가 사라지는 것 |
| 5 | **프로파일 드리프트** | `python scripts/check_profile_drift.py` | 차이가 전부 선언돼 있을 것 | ★현장 프로파일이 기본값에 뒤처지는 것 |

### 5번이 실제로 막은 것
학원 프로파일에 키 **6개**(proximity 2 · retention 3 · zone 1)가 누락돼
[F5](전역 구역 폴백 차단)·[F6](자동 파기)가 **학원에서 무효화될 뻔했다.**
프로파일이 `copy`로 파일 전체를 덮는 방식이라 기본값에 키가 추가되면 조용히 뒤처진다.
→ 이제 선언 없는 차이는 **실패**다(`deploy/academy/profile_intent.yaml`에 이유와 함께 선언).

## 2. CI — ★있지만 반쪽이다

`.github/workflows/ci.yml` 이 위 5종을 **그대로** 실행한다(Python 3.13, ubuntu).

```yaml
on:
  push:         branches: [main]
  pull_request: branches: [main]
```

| 질문 | 정직한 답 |
|---|---|
| CI가 있나 | ⭕ 있다. 게이트 5종 전부 자동 실행 |
| **지금 작업 브랜치에서 도나** | ❌ **안 돈다.** 현재 브랜치는 `fix/review-bugs`이고, CI는 **`main` 대상 push/PR에서만** 돈다 |
| **그럼 누가 돌리나** | ★**사람이 매번 로컬에서 돌린다.** 커밋 메시지마다 게이트 결과를 적어 두는 방식으로 강제한다 |
| 이게 안전한가 | ❌ 안전하지 않다. **깜빡하면 그냥 넘어간다.** 개선 항목이다 |
| CI에서 검출 테스트가 도나 | ❌ 안 된다. 러너에 커스텀 가중치(`.gitignore` 대상)가 없어 `VIGENT_ALLOW_FALLBACK=1`로 돌린다 |

## 3. 셔플 검증 — 순서 의존 결함 잡기

```bash
python scripts/run_tests_shuffled.py --runs 10 --seed-base 300
```

| | |
|---|---|
| 왜 | 배경 스레드가 남긴 결함은 **실행 순서에 따라 나타났다 사라진다.** 고정 순서로 몇 번 통과했다고 "해결"이라 하면 근거가 부족하다 |
| 어떻게 | 회차마다 **별도 프로세스**로 `unittest discover`, 순서만 셔플 |
| ★설계 이유 | 처음엔 한 프로세스에서 10회 돌렸는데 회차 간 상태가 쌓여 **없는 결함을 만들었다.** 실제 게이트와 같게 프로세스를 분리해야 신호가 남는다 |
| 성과 | **운영 결함 3건 + 테스트 결함 1건** 발견([07](07_개발_규칙과_그_사연.md)) |
| 최종 | seed 301~310 · **10/10 통과** |
| ★한계 | "결함이 없다"는 증명이 **아니다.** 10회에서 재현되지 않았다는 관측일 뿐이다 |

## 4. 현장 촬영 검증 — `check_raw_capture.py`

```bash
python scripts/check_raw_capture.py runs/field_<날짜>
```

장면마다 `original.mp4` 존재·크기·**실제로 열려 프레임이 나오는지** + 원본 스틸 수 + `dets` 행수를 대조.
★**검사 대상이 0개면 통과가 아니라 실패**로 보고한다.

**1차 자료에 돌려 11장면 전부 실패로 잡히는 것을 확인**했다 — 도구가 실제로 작동한다.

## 5. ★테스트가 실제로 무엇을 덮나 (모르는 것 포함)

| 질문 | 답 |
|---|---|
| 481건이 무엇을 보나 | **배선·상태기계·설정 안전장치.** 예: 쿨다운 키 격리, 트랙 키 TTL, `ppe.required` 무효 설정, 프로파일 드리프트, 헬스 결함 주입 |
| **검출 정확도를 검증하나** | ❌ **아니다.** 정확도는 `benchmarks/`의 별도 측정이고 게이트에 없다 |
| **검출 경로를 몇 % 덮나** | ★**모른다.** 커버리지를 **측정한 적이 없다.**<br>`coverage`·`pytest-cov` 설정이 저장소에 **없다**(전수 검색) |
| 그럼 무엇으로 아나 | 파일명으로 짐작할 뿐이다: 검출·추적 관련 17파일이 있다.<br>★**이것은 추정이지 측정이 아니다** |
| 통합 테스트가 있나 | 부분적. `test_worker_process_frame`·`test_alert_wiring`이 프레임→발화→통보 배선을 본다.<br>실제 카메라·실제 모델로 도는 종단 테스트는 **없다** |

### 이 공백이 위험한 지점
- 모델을 갈아끼워도 **게이트는 전부 초록**이다. 성능 저하를 게이트가 못 잡는다.
- → 그래서 **규칙 9**(구성 바뀌면 기준선 재측정)가 규칙으로 존재한다. **사람이 지켜야 하는 규칙**이다.
- 이걸 자동화하려면 **정답지가 필요하다.** 그게 지금 없다([09](09_앞으로_6개월.md)).
