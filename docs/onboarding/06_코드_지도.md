# 06. 코드 지도 — 무엇부터 읽나

## 읽는 순서 (핵심 8파일, 3,909줄)

```
1. worker.py        ← 여기부터. 전체 흐름이 여기 있다
2. agents/guard.py  ← 검출·추적·파생신호
3. alert_gate.py    ← 억제 정책(짧다, 153줄)
4. alert_queue.py   ← 기록 우선 큐
5. alert_notify.py  ← 전송 스레드
6. agents/dispatcher.py ← 실제 전송(텔레그램/메일/웹훅)
7. privacy.py       ← 얼굴 비식별화
8. retention*.py    ← 자동 파기
```

## ★함정 (모르면 잘못 읽는다)

| 함정 | 실제 |
|---|---|
| ★**`dets.jsonl`은 추적 이후만 담는다** | 검출됐다가 추적이 버린 것은 **기록에 없다.** "안 잡혔다"와 "버렸다"를 구분하려면 `_pre_track`이 필요한데 **기록되지 않는다** |
| ★**`dets.jsonl`은 임계 통과분만 담는다** | 낮은 confidence 후보는 없다. "검출 없음"과 "임계 미달"을 구분하려면 `guard.detect(conf=0.05)`로 **다시 돌려야** 한다 |
| ★**`_cross_validate_ppe`는 추적보다 먼저 실행된다** | `guard.py:944` → `949`. 그래서 추적이 사람을 버리면 **PPE 라벨만 남는다**(실측 57건) |
| **"fallback: heuristic" 표기는 거짓이었다** | `vision.yaml`에 있던 폴백 표기는 **구현·소비 0건**. 모델이 없으면 그 슬롯은 아무것도 못 본다. 2026-08-24에 정정 |
| **`ppe_missing`의 subject는 항상 `""`** | 카메라 단위다. 사람 단위 귀속이 아니다 |
| **`DETECT_LOCK`은 RLock이다** | 재진입 경로(VLM 확정 체인)가 있어 일반 Lock이면 자기 데드락 |
| **`main.py`를 import하면 스레드가 뜬다** | `alert_queue.start()` 등이 startup에 배선돼 있다. 테스트에서 이것 때문에 실제 결함 2건이 드러났다 |
| **한글 경로에서 `cv2.imwrite`는 조용히 실패** | 예외 없이 `False`만 돌려준다. 프로젝트 전체가 `imencode` + `write_bytes` + **존재 확인**을 쓴다 |
| **OpenCV는 한글 경로 영상을 못 연다** | `VideoCapture`도 마찬가지. ASCII 경로로 복사해서 처리한다 |
| **Windows 한글 파일명은 NFC/NFD가 섞인다** | OneDrive 쪽과 저장소 쪽 정규화가 달라 대조가 어긋난다. `unicodedata.normalize("NFC", …)` 필수 |
