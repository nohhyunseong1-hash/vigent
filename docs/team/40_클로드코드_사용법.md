# 40. Claude Code 사용법 ★ 바이브코딩 규칙

> **우리 팀은 Claude Code 하나만 씁니다.** 이유: 도구가 여러 개면 팀원마다 환경·습관이 갈려 협업이 깨집니다. 하나로 통일하면 지시문·문제해결 방식을 공유할 수 있습니다.

## 설치·실행 (화면 흐름)

1. 터미널을 엽니다 (macOS: Spotlight에서 "터미널" / Windows: PowerShell). 상세는 `50_완전초보_온보딩.md`.
2. 프로젝트 폴더로 이동합니다.
```bash
cd ~/Desktop/VIGENT
```
실행하면 이런 게 보입니다:
```
(아무 메시지 없이 프롬프트가 VIGENT 폴더로 바뀝니다)
```
3. Claude Code를 실행합니다.
```bash
claude
```
실행하면 이런 게 보입니다:
```
╭──────────────────────────────╮
│  Claude Code                 │
│  > (여기에 지시를 입력)       │
╰──────────────────────────────╯
```

## 좋은 지시문 4원칙

1. **목적 먼저** — "무엇을 왜" 한 줄로.
2. **건드릴 파일 범위 명시** — 어느 파일까지 만져도 되는지.
3. **완료 조건 제시** — 무엇이 되면 끝인지(숫자로).
4. **한 번에 하나** — 여러 개를 한꺼번에 시키지 않기.

## 나쁜 지시문 vs 좋은 지시문 (이 프로젝트 실제 작업으로)

**예시 1 — 정확도 측정**
- 🔴 나쁨: "정확도 좀 봐줘"
- 🟢 좋음: "person·PPE·fire/smoke 클래스별 precision·recall·F1을 산출하는 스크립트를 `tools/`에 만들어줘. 기존 `benchmarks/` 코드를 재활용하고, 측정 환경(MPS/CPU)을 리포트에 병기해줘. 코드 수정 전 계획 먼저 보여줘." (V-02 티켓)

**예시 2 — 추적기 교체**
- 🔴 나쁨: "추적 더 좋게 바꿔"
- 🟢 좋음: "추적기 A/B 결과 SORT가 단편화가 심해. `rfdetr_service.py`·`rfdetr_zone_track.py`의 SORTTracker를 ByteTrackTracker로 교체하는 계획을 먼저 보여주고, 게이트(테스트 82) 통과 확인 후 커밋해줘. 다른 파일은 건드리지 마."

**예시 3 — 연동 배선**
- 🔴 나쁨: "감지된 거 서류에 자동으로 넣어줘"
- 🟢 좋음: "`data_engine.log_event → scribe.build_checklist` 경로를 조사해줘. 지금은 빈도만 재사용하는데, 감지 규칙이 체크리스트 항목을 자동 X로 반영하도록 바꾸는 설계를 **계획으로 먼저** 보여줘. 미감지 항목은 '수동확인' 유지. `golden_regression` 회귀 없게." (A-01 티켓)

## 작업 흐름 (반드시 이 순서)

```
① 지시 입력  →  ② "계획 먼저 보여줘" 요청  →  ③ 계획 확인 후 "진행해" 승인
   →  ④ 결과·게이트 확인  →  ⑤ 커밋
```
- **핵심**: 코드를 바꾸는 지시는 **항상 계획을 먼저 받고** 승인하세요. 바로 실행시키지 않습니다.

## CLAUDE.md 가 뭔가

- 프로젝트 루트의 `CLAUDE.md`는 **Claude Code가 매 대화마다 자동으로 읽는 규칙서**입니다.
- 여기 규칙을 적어두면 모든 팀원의 Claude Code가 같은 규칙으로 동작합니다.
- 규칙 추가법: "CLAUDE.md에 '~~ 규칙을 추가해줘'"라고 지시하면 됩니다. (단, 팀 합의 후)

## 세션 관리

- 대화가 길어지면 **한 작업 끝 → 커밋 → 새 대화 시작**. 짧게 끊어야 Claude가 헷갈리지 않습니다.
- **작업 단위로 커밋**하세요. 한 커밋에 여러 작업을 몰지 마세요.

## 절대 하지 말 것

- ❌ 확인 없이 **대량 파일 수정을 승인**하기
- ❌ **이해 못 한 코드를 커밋**하기 (뭐 하는지 물어보고 이해한 뒤 커밋)
- ❌ **에러를 숨기고 다음 단계로** 넘어가기 (에러는 반드시 해결·공유)

## 막혔을 때 3단계

1. **에러 메시지 전문을 복사** (일부만 말고 전체).
2. **Claude Code에 붙여넣기** + "이 에러가 났어. 원인과 해결을 알려줘".
3. 그래도 안 되면 **팀 채널에 에러 전문 공유**.
