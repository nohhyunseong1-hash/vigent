# 80. 용어 사전

> 이 리포에서 **실제로 쓰이는 용어**만 모았습니다. 각 항목 = 한 줄 정의 + "우리 프로젝트에선 이렇게".

## 개발·협업

| 용어 | 정의 | 우리 프로젝트에선 |
|---|---|---|
| 커밋(commit) | 작업 내용을 한 시점으로 저장하는 것 | "작업 단위로 커밋" — 한 번에 하나 |
| 브랜치(branch) | 내 작업만 담는 분리된 공간 | `feat/내작업이름`으로 만들어 작업 |
| PR(Pull Request) | 내 브랜치를 main에 합쳐달라는 요청 | 승인 없이 merge 금지 |
| 머지(merge) | 브랜치를 합치는 것 | PR 승인 후에만 |
| 게이트(gate) | 커밋 전 통과해야 하는 검사 | ruff·mypy·테스트 82·OpenAPI 무변경 |
| 스텁(stub) | 껍데기만 있고 실동작 안 하는 코드 | Coach 에이전트(12줄) |
| fail-fast | 문제 시 조용히 넘어가지 않고 즉시 멈춤 | 가중치 없으면 폴백 대신 멈추기(V-01) |
| 폴백(fallback) | 실패 시 대체 동작 | 가중치 없으면 COCO로 폴백(주의: 정확도↓, F-8) |

## 비전(L1)

| 용어 | 정의 | 우리 프로젝트에선 |
|---|---|---|
| mAP | 검출 정확도 종합 지표(0~1) | fire/smoke 공개셋 mAP@50 80.13% |
| precision(정밀도) | 잡았다고 한 것 중 맞은 비율(오탐의 반대) | **대부분 미측정** — 재측정 필요 |
| recall(재현율) | 실제 위험 중 잡아낸 비율(미탐의 반대) | PPE·person 수치는 대부분 recall만 |
| F1 | precision과 recall의 조화평균 | KISA 기준 F1≥0.90 (현재 미산출, V-02) |
| 추론 지연(latency) | 한 프레임 처리에 걸리는 시간(ms) | 타일 +415ms/f(CPU) |
| RF-DETR | 우리가 쓰는 객체 검출 모델 | 검출 코어(`rfdetr_service.py`) |
| 포즈 추정(pose) | 사람 관절 위치 추정 | RTMPose/yolov8n-pose (`ergonomics.py`) |
| 추적(tracking) | 프레임 간 같은 사람에 같은 ID 부여 | ByteTrack(SORT에서 교체) |
| ByteTrack | 우리가 채택한 추적 알고리즘 | ID 스위치 0으로 개선 |
| 타일링 | 위험구역만 잘라 재검출해 소형작업자를 잡는 기법 | recall 0→89~95%(단 +415ms) |
| MPS | 애플 칩(맥)의 GPU 가속 | 현재 개발환경(배포는 CUDA) |
| CUDA | NVIDIA GPU 가속 | 배포·재학습 목표 환경 |
| 엣지(edge)/RK3588 | 현장 저전력 소형 처리장치 | 포팅 검토 단계(코드 없음) |

## 에이전트(L2)

| 용어 | 정의 | 우리 프로젝트에선 |
|---|---|---|
| 에이전트(agent) | 특정 역할을 맡는 AI 모듈 | Scribe·Copilot·Guard 등 6개 |
| 골든셋(golden set) | 정답이 있는 평가용 표본 | 체크리스트 3건 + 홀드아웃 15케이스 |
| 채점 엔진 | 산출물을 정답과 비교해 점수화 | `golden_regression.py` |
| 베이스라인 | 회귀(나빠짐) 감지 기준선 | **품질 합격선 아님** — 정답 확정 아님 |
| 화이트리스트 | 허용된 법령 조문 목록 | 밖의 조문 인용은 차단(F-11) |
| 환각(hallucination) | AI가 없는 사실·조문을 지어냄 | crane 골든서 4건 관찰 |
| 상태기계 | 조건에 따라 상태가 전이되는 로직 | RIG 모듈(세부는 대외비) |
| LLM | 대형 언어모델(텍스트 생성 AI) | OpenAI/Anthropic(외부 API) |
| 온프렘(on-prem) | 외부 클라우드 없이 자체 장비에서 실행 | 폐쇄망 대응 과제(현재 미지원) |
| 폐쇄망 | 인터넷이 차단된 내부망 | 공장 다수의 조건(S5) |
