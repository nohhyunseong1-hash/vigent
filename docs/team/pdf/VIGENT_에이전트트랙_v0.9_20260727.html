00. 시작하기 전에 (3분 요약)

이 문서는 팀원 전원(대표 포함)이 가장 먼저 읽는 문서입니다. 바이브코딩·팀 프로젝트가 처음이어도 괜찮습니다.

VIGENT가 뭘 만드는 회사인가 (5줄)

  1. VIGENT는 공장·건설현장의 CCTV 영상을 AI가 보고 위험을 잡아내는 산업안전 플랫폼입니다.
  2. 카메라가 "위험구역에 사람이 들어왔다 / 보호구를 안 썼다 / 불·연기가 났다"를 자동으로 감지해 경보합니다. (이것을 비전(Vision, L1)이라 부릅니다.)
  3. 감지 결과로 위험성평가서 같은 안전 서류를 AI가 자동 작성합니다. (이것을 에이전트(Agent, L2)라 부릅니다.)
  4. 즉 "보는 눈(비전) + 판단하는 머리(에이전트)"가 한 시스템으로 붙어 있습니다.
  5. VIGENT는 보조 감시 도구입니다 — 법으로 정해진 안전장치(방호장치 등)를 대체하지 않고, 추가로 지켜보는 신호를 줍니다.

지금 어디까지 왔나 (3줄)

  • 비전·에이전트 코드와 자체 테스트(82개 통과)는 갖춰졌고, 동시부하 크래시(F-14) 같은 큰 안정성 문제는 해결했습니다.
  • 하지만 실제 현장 CCTV로 정확도를 잰 적이 거의 없습니다(실영상 검증 1건). 공개 데이터셋 수치만 있습니다.
  • 감지 클래스는 3클래스 가동(person·PPE·fire/smoke) + forklift(지게차)는 재학습 대기입니다.

앞으로 뭘 할 건가 (3줄)

  • 비전(L1): 현장 영상으로 정확도(오탐·미탐)를 재고, 부족한 클래스(안전모 미착용 등)를 재학습해 KISA 인증 기준(F1 ≥ 0.90)을 향합니다.
  • 에이전트(L2): AI가 만든 안전서류의 품질을 계측하고, 잘못된 법령 인용(환각)을 막고, 비전 감지와 자동 연동합니다.
  • 두 트랙이 만나 파일럿(시범 설치) → 유상 납품으로 갑니다. 상세 단계는 10·20 문서에 있습니다.

지금 당장 팔 수 있는가? (정직한 답 3줄)

(2) 상용화 단계 정의 (S0~S6)

단계 이름 완료 판정 기준(숫자) 현재 상태 남은 작업 예상 소요(추정)
S0 ▶ 파이프라인 구현 6에이전트 전부 실동작 + 산출물 1건 end-to-end 🟡 4개 실동작·Coach 스텁(12줄), 위험성평가서 1건 실동작 Coach 구현 or 범위 확정 2~3일
S1 ▶ 품질 계측 체계 골든셋 N건 + 채점 엔진 + 평균 점수 기록 🟢 회귀 엔진 + 홀드아웃 15케이스(합격 11/15) 골든 확대·절대품질 강사 재검수 진행중
S2 환각·법령 통제 화이트리스트 밖 조문 인용 0건 + 차단 로그 남음 🟡 차단 로직 있음(F-11) / 차단 로그 잔존 [측정 필요] 차단 로그 확인·환각 4건 원인 분석 3~5시간
S3 L1 연동 비전 이벤트 → 체크리스트 자동 반영 경로 실동작 🔴 미완 — 현재 빈도 통계 재사용(count→_likelihood), 항목 자동 O/X 아님 라이브 감지→항목 O/X 자동반영 배선(A-01) [측정 필요]
S4 현장 수용성 검증 실제 안전관리자 N명 리뷰 통과 + 수정요청 반영 🔴 미착수 관리자 리뷰 세션 현장 의존
S5 폐쇄망 대응 외부 API 없이 온프렘 LLM으로 동일 품질 재현 🟡 핵심(법령·위계·빈도)은 규칙기반=오프라인 동작 / 텍스트 LLM은 외부 API(OpenAI·Anthropic)뿐, 온프렘(ollama) 제거됨 종합의견용 온프렘 LLM 재도입·로컬 VLM 대안 1~2주
S6 유상 납품 첫 유상 계약 / 구독 전환 🔴 미착수 파일럿 후 장기

▶ 현재 위치 = S0~S1 병행 (파이프라인 대부분 실동작 + 품질 계측 시작. 단 S3 연동은 미완).

각 단계를 건너뛰면 어떤 사고가 나는가

  • S0 생략 → 산출물이 end-to-end로 안 나와 데모조차 불가.
  • S1 생략 → 품질을 못 재서 코드 바꿀 때마다 몰래 나빠져도 모름(회귀).
  • S2 생략 → 잘못된 법령 조문이 고객 문서에 그대로 실림(신뢰·법적 리스크).
  • S3 생략 → 비전이 잡은 위험이 서류에 자동 반영 안 됨 → "AI 자동화"라는 핵심 가치 상실(수동 입력과 다를 바 없음).
  • S4 생략 → 현장 안전관리자가 안 쓰는 서류를 만들게 됨(수용성 0).
  • S5 생략 → 폐쇄망(인터넷 차단) 공장에서 종합의견 생성 불가.

S3·S5 판정 근거 (감사 실측)

  • S3: agents/scribe.py:129,585가 이벤트의 count(빈도)를 _likelihood로 변환해 쓰고, 감지 규칙→적정성 X 매핑은 요청 시 events를 넘겨받아 처리. data_engine.py:6 "빈도 집계로 재사용" 명시 → 라이브 자동 O/X 파이프라인 아님 = 미완. 확인: sed -n '129,130p;585,586p' vigent-core/agents/scribe.py
  • S5: llm_provider.py:1-13 — provider=openai/anthropic(둘 다 외부), ollama(온프렘) 제거됨(2026-07-14). 단 법령·위계·빈도는 규칙기반이라 LLM 없이 동작. 확인: sed -n '1,13p' vigent-core/llm_provider.py

(4) 비전 트랙과의 연결점 (어느 A가 어느 V에 막혀 있나)

A 티켓 막혀 있는 V 티켓 이유
A-01(이벤트→체크리스트 자동반영) V-01(가중치 fail-fast) 자동반영이 신뢰 있으려면 검출이 폴백 없이 제대로 돌아야 함(F-8)
A-02(환각·차단로그) — 독립(법령 로직은 검출과 무관)
A-05(강사 재검수) V-05(현장 오탐 샘플) 실제 감지 결과라야 서류 품질이 현장 의미를 가짐
A-07(온프렘 LLM) V-08(엣지 포팅) 폐쇄망·엣지 배포는 함께 묶여 감(온프렘 환경)

이 트랙의 3대 리스크

  1. 환각(잘못된 법령 인용)이 고객 문서에 실림 — 신뢰·법적 리스크.
    • 조기 경보: A-02에서 차단 로그가 실제로 안 남거나, 환각 건수가 골든 확대 시 늘면.
  2. L1↔L2 연동 미완이 방치됨 — "AI 자동화" 가치가 비어 파일럿 설득력 하락.
    • 조기 경보: A-01이 계속 뒤로 밀리고 데모가 여전히 수동 입력이면.
  3. 폐쇄망 대응 공백 — 공장 다수가 인터넷 차단 → 외부 API 의존이 납품 장벽.
    • 조기 경보: 파일럿 후보가 "인터넷 안 됨"을 조건으로 내거는데 온프렘 대안이 없으면.
