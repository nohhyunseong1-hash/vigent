## 1. 결론 — 예산을 어디에 쓸 것인가

| 순위 | 항목 | 이유 |
|---|---|---|
| **1** | **CPU (코어 수 × 코어당 성능)** | 병목이 여기다. 카메라당 **2.1 논리코어** 소모 |
| 2 | RAM 16GB · NVMe SSD 256GB | 넉넉하면 그만. 병목 아님 |
| **3(최소만)** | **GPU — VRAM 6~8GB CUDA 카드면 충분** | 카메라 **8대**에서도 **GPU 사용률 16~42%**. 비싼 GPU 를 사도 **대수가 늘지 않는다** |

### 가장 중요한 한 줄

> **GPU 에 돈을 쓰면 낭비다. 같은 예산이면 GPU 를 최저 사양으로 내리고 CPU 에 몰아라.**

E1 실측: 포화 시점에 **CPU 는 79~99%, GPU 는 16~42%** 였다. GPU 를 두 배 빠른 것으로
바꿔도 놀고 있는 자원이 더 놀 뿐이다.

★**실서비스 직접 계측으로 확인된 포화 신호**: 8번째 카메라를 붙이면 그 카메라가 받는 CPU 가
앞선 카메라들의 **절반(208%→109%)** 으로 떨어지고, 그 부족분을 **지연 악화**(실카메라 p95
139→159ms)로 값을 치른다. CPU 가 다 떨어졌다는 뜻이다.

### 두 번째로 중요한 한 줄

> **"CPU 디코드가 병목"은 사실이 아니다 — 디코드는 프레임당 1ms 미만이다.**

따라서 **NVDEC(하드웨어 디코더)·고해상도 대응 같은 항목에 돈을 쓰지 말 것.**
CPU 를 먹는 것은 **추론의 전·후처리 연산**이다(E1 §1 H4).

## 2. 산정 공식 (실측 유도)

```
카메라 1대 = 2.1 논리코어  (개발기 기준, 카메라당 2fps)
   └ 검출 1.43 코어(70%) + 검출 밖 파이프라인 0.65 코어(30%)

한계 N  ≈  논리코어 수 × 0.70 ÷ 2.1
권장 N  =  한계 N × 0.75
```

**검증 1**: 개발기 24스레드 → 공식 8.0대, C5 실측 한계 **7대**. 공식이 약간 낙관적이므로
구매 판단에는 보수적으로 쓴다.

**검증 2(독립 교차검증)**: C-1(2026-08-11)이 **같은 개발기**에서 카메라당 **1fps** 로
"16대까지 미포화"를 실측했다. E1 값을 1fps 로 환산하면 1.05코어/대 → 24×0.70÷1.05 =
**16.0대**. **서로 다른 두 실험이 일치한다.**

### ⚠ 공식을 다른 CPU 에 쓸 때 — 반드시 코어당 성능으로 보정

`2.1 코어`는 **4.4GHz Zen5(Ryzen 9 9900X)** 기준이다. 구형·저클럭 CPU 는 코어 수가 같아도
느리다. 보정은 이렇게 한다:

```
필요 스레드 = (원하는 대수 × 2.1 ÷ 0.70) ÷ 성능계수
성능계수 = (후보 CPU 단일스레드 점수) ÷ (Ryzen 9 9900X 단일스레드 점수)
```

★**우리는 이 성능계수를 측정하지 않았다.** 공개 벤치 점수로 계산한 값은 **추정**이며,
확정은 §7 인수시험뿐이다.

## 3. 사양표

### 3-A. 파일럿 (카메라 1~2대) — 30~50만원 예산으로 **가능**

| 항목 | 최소 | 권장 | 근거 |
|---|---|---|---|
| **CPU** | **9900X급 6스레드 상당**<br>(구형이면 성능계수로 환산해 더 필요) | 8스레드 상당 + 여유 | 2대 × 2.1 ÷ 0.70 = **6.0** |
| **GPU** | NVIDIA CUDA, **VRAM 6GB** | VRAM 8GB | 상주 실측 **3,205~3,239 MiB** + 여유 |
| RAM | 16GB | 32GB | 소크 실측 RSS ≈ 3.2GB + OS·torch |
| 저장 | SSD 256GB | NVMe 500GB | 실사용 실측 ≈ **40GB**(§4) |
| OS | **Windows 10/11** | 동일 | §5 — 현재 배포·암호화 검증이 Windows 의존 |

### 3-B. 소형 현장 (카메라 4~5대) — 30~50만원 예산으로 **보증 불가**

| 항목 | 최소 | 근거 |
|---|---|---|
| **CPU** | **9900X급 15스레드 상당** | 5대 × 2.1 ÷ 0.70 = **15.0** |
| GPU / RAM / 저장 / OS | 3-A 와 동일 (대수와 무관) | GPU util 은 8대에서도 16~42% |

> ### 🔴 정직한 경고
> **"9900X급 15스레드 상당"을 30~50만원 중고로 맞추기는 어렵다.** 구형 CPU 는 성능계수가
> 1 미만이라 물리 스레드가 15개여도 부족할 수 있고, 우리는 그 계수를 **측정하지 않았다**.
> 이 예산에서 **확실히 말할 수 있는 것은 1~2대뿐**이다.

### 3-C. 예산 안에서 4~5대를 노리는 유일한 실측 기반 수단

**카메라당 fps 를 2 → 1 로 낮추면 소요가 절반**이 된다(C-1 실측 + E1 환산 일치, §2 검증2).
같은 박스로 대수가 **2배**가 된다.

⚠ **그러나 이것은 규칙6(기능 저하 금지) 대상이라 여기서 결정하지 않는다.** 검출 주기가
0.5초 → 1.0초가 되면 **존 침입 디바운스(`zone.enter_s` = 1.0초)와 충돌**해 침입을 놓칠 수
있다. 채택하려면 **별도 승인 + 침입 검출률 재측정**이 선행돼야 한다.

## 5. Windows 가 필요한 이유 (코드 근거)

현재 배포 경로는 Windows 에 묶여 있다. Linux 이식은 **가능하지만 재작업이 필요하고
검증되지 않았다.**

| 의존 | 위치 |
|---|---|
| 서비스 등록(재부팅 자동 기동) = **NSSM** | `deploy/windows/install_service.ps1` |
| 저장 암호화 검사 = **`cipher /c`** | `vigent-core/privacy.py:175` |
| 볼륨 암호화 검사 = **`Get-BitLockerVolume`** | `vigent-core/privacy.py:199` |
| 배포·상태 점검 스크립트 | `deploy/windows/*.ps1` |

→ **Windows 라이선스가 포함된 중고 PC** 를 사는 편이 총비용에서 유리하다.

## 6. ❌ 사지 말아야 할 것

| 사지 말 것 | 이유(실측 근거) |
|---|---|
| **비싼 GPU** | 8대에서도 GPU util **16~42%**. 대수가 늘지 않는다 — 순수 낭비 |

| **아주 오래된 GPU**(Kepler·Maxwell 등) | 최신 torch(cu130) 가 지원을 끊었을 수 있다 — §7 에서 반드시 확인 |

## 7. 중고 구매 체크리스트

### 구매 **전** 확인

- [ ] CPU 논리스레드 수 확인 → §2 공식으로 대수 계산(성능계수 보정 포함)
- [ ] GPU 가 **NVIDIA CUDA** 이고 **VRAM ≥ 6GB**
- [ ] 해당 GPU 가 **현재 torch(cu130) 지원 대상**인지 확인 (구형 아키텍처 지원 중단 주의)
- [ ] RAM ≥ 16GB (증설 슬롯 여유 확인)
- [ ] SSD ≥ 256GB
- [ ] **Windows 정품 라이선스 포함** 여부
- [ ] 전원 용량이 GPU 를 감당하는지 · 설치 공간·발열·소음
- [ ] **반품·교환 가능 조건** ← 인수시험에서 떨어질 수 있으므로 **필수**

### 구매 **후** 인수시험 (★이 절차 전에는 대수를 약속하지 않는다)

1. Windows·드라이버·Python 3.11 설치
2. `python scripts/fetch_weights.py` — 가중치 조달
3. `deploy/windows/install_service.ps1` — 서비스 등록
4. `/health` 가 `status=healthy phase=ready` 인지 확인
5. **`python scripts/capacity_probe.py --max-n 8 --hold 180`** ← **핵심**
6. 결과의 **한계 N × 0.75** 를 그 박스의 **권장 대수로 확정**하고
   `benchmarks/capacity_report.md` 에 기종명과 함께 추가 기록
7. 한계 N 이 목표에 미달하면 **반품**하거나 §3-C(fps 하향, 별도 승인 필요)를 검토

## 8. 이전 "저가 엣지박스" 결정의 현재 유효성 — ❌ **무효**

### 8-1. 이전 결정의 실제 내용

`docs/ops_capacity_sizing.md`(C-1, 2026-08-11)의 결론은 다음과 같았다:

- §3 표: *"CPU 전용 미니PC 25만원 → **약 8대**(추정/미검증)"*
- §3.1: **그 8대를 스스로 보류**했다 — *"§3의 «CPU 전용 미니PC(25만원) → 약 8대»는 이
  재검증으로 보류한다"*
- §3.1 최종: *"**중간급(40~60만원대, 중고 사무용 i5) 경로를 기본으로 확정한다**
  … N100급은 카메라 1~2대의 초소형 현장에 한해 조건부 후보"*

### 8-2. 그 결정이 서 있던 두 전제 — 둘 다 지금은 성립하지 않는다

| 전제 | 당시 | 현재 | 영향 |
|---|---|---|---|
| **카메라당 1fps** | 모든 실측이 1fps | 운영 기본 **2fps**(`worker.fullset_fps: 2`, C5·E1 모두 2fps) | **소요 2배 → 대수 절반** |
| **ONNX fp32 CPU 백엔드로 1.85배 이득** | "적용하면" 기준으로 환산 | **적용되지 않았다** — 검출 경로에 ONNX 없음(`.pth`/torch). `onnx` 는 얼굴 익명화(YuNet)에만 쓰인다(`privacy.py:65`) | **가정한 1.85배 이득이 실재하지 않음** |

> C-1 §3.1 자신이 이미 *"아직 실제 서빙 코드에는 반영하지 않았다"* 고 적어뒀고,
> 그 상태가 오늘까지 그대로다(확인: `vigent-core/` 검출 경로에 onnxruntime 미사용).

### 8-3. 추가된 제약

| 항목 | 내용 |
|---|---|
| RF-DETR 필수화 · YOLO 폴백 차단 | 4슬롯 RF-DETR 로 고정 — 가벼운 폴백으로 도망갈 길이 없다 |
| E1 실측 | 병목이 **CPU 추론 전·후처리**로 확정 → CPU 사양이 곧 대수 |

### 8-4. 판정

| 항목 | 판정 |
|---|---|
| "25만원 미니PC → 8대" | ❌ **무효** (C-1 §3.1 이 이미 보류했고, 2fps 로 더 멀어졌다) |
| "중고 i5 40~60만원 → 2~4대" | ❌ **현 조건에서 무효** — 1fps·ONNX 두 전제가 모두 깨졌다. 같은 박스면 **1~2대 수준으로 축소**될 것으로 **추정**(미측정) |
| "N100급 → 1~2대" | ❌ **무효** — 카메라당 2.1코어라 4코어로는 **1대도 빠듯** |
| **현재 유효한 결론** | **30~50만원 예산 = 파일럿 1~2대.** 4~5대는 이 예산에서 **보증 불가**이며, §3-C(fps 하향, 별도 승인 필요) 또는 예산 상향이 필요하다 |

★C-1 의 **측정값 자체는 틀리지 않았다**(E1 과 1fps 환산에서 정확히 일치). 무효가 된 것은
**운영 조건(fps)이 바뀌었고 가정했던 최적화(ONNX)가 적용되지 않았기 때문**이다.

## 9. 이 문서가 측정하지 않은 것 (규칙7)

| 항목 | 상태 |
|---|---|
| 개발기 외 CPU·GPU 의 절대 성능 | **미측정** — 성능계수는 공개 벤치 기반 추정일 뿐 |
| 구체적 기종·가격 | **조사하지 않았다** — 이 문서는 요구 조건만 정의한다 |
| 1fps 운전 시 침입 검출률 | **미측정** — §3-C 채택 전 필수 |
| ONNX 서빙 전환 시 실제 이득 | 개발기 단일 슬롯 1.85배 추정치뿐. 4슬롯·서비스 통합 시 이득은 **미측정** |
| Linux 이식 비용·성능 | **미검증** |
