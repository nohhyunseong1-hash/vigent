# 실카메라 2인 추적 시험 절차서 (P2c)

> 감사 🟠C6. 오프라인 평가(`benchmarks/eval_tracking_2026-08-18.md`)에서 ByteTrack 이 iou 보다
> 나음을 확인했으나, **오프라인은 15~24fps 이고 실서비스는 2.3fps** 라 간극이 있다.
> 이 절차서는 그 간극을 실카메라로 메우기 위한 것이다.
>
> **필요 인원: 2명** · 소요: 약 20분 · 서비스는 평소대로 실행 중이면 된다.

## 1. 시나리오 (각 60초)

### S1. 교차 보행
두 사람이 화면 양끝에서 마주 걸어와 **가운데서 서로 지나친다**. 3회 반복.

| 확인 | 합격 기준 |
|---|---|
| 교차 직후 각자의 id | **교차 전과 동일**해야 한다 |
| id 개수 | 시나리오 내내 **2개 유지**(3개 이상 = 파편화) |
| 확인 방법 | 확대뷰 박스 숫자 + 기록 파일의 id 집합 변화 |

**실패 예**: 교차 순간 A↔B 의 id 가 서로 뒤바뀜(ID swap) — 이게 ByteTrack 채택의 핵심 목적이라
여기서 실패하면 채택 재검토 대상이다.

### S2. 가림(한 명이 다른 한 명을 가림)
A가 서 있고, B가 A **앞을 가로질러** A를 3~5초 완전히 가린다. 3회 반복.

| 확인 | 합격 기준 |
|---|---|
| A의 id | 가림 해제 후 **가림 전과 동일** |
| 가림 중 인원 카운트 | 1명으로 떨어져도 정상(검출에 충실) — **경보 플래핑 여부**를 함께 본다 |

> 참고: 가림 중 카운트가 떨어지는 것은 알려진 특성이다(백로그 PM-2). 이 시험은 **id 복원**이 초점.

### S3. 동시 진입
두 사람이 **같은 쪽에서 나란히 동시에** 프레임에 들어온다. 3회 반복.

| 확인 | 합격 기준 |
|---|---|
| 진입 즉시 id | **서로 다른 2개**가 부여된다(하나로 뭉치지 않는다) |
| 확정 지연 | 진입 후 **2초 이내** 두 id 모두 표시 |

### S4. 근접 대화(정지 상태 밀착)
두 사람이 **팔 닿을 거리로 마주 서서** 30초간 대화하듯 정지. 1회.

| 확인 | 합격 기준 |
|---|---|
| id 유지 | 30초 동안 **두 id 모두 안정 유지**(깜빡임 없음) |
| 박스 병합 | 두 박스가 하나로 합쳐지지 않는다 |

**실패 예**: 밀착 상태에서 두 트랙이 하나로 합쳐졌다가 떨어질 때 id 가 뒤바뀜.

### S5. 한 명 이탈 후 재진입
A는 계속 프레임 안에 있고, B만 나갔다가 **5초 / 30초 / 60초** 후 각각 재진입. 3회.

| 확인 | 합격 기준 |
|---|---|
| A의 id | B가 나가고 들어오는 내내 **불변** |
| B의 재진입 id | **판정 기준을 정하지 않는다** — 아래 설명 |

> ★B의 id 가 유지되는지 새로 발급되는지는 **현재 합격/불합격을 매기지 않는다.**
> 백로그 PQ 에서 확인했듯 person 0명 구간에서는 트래커가 멈추고, 1명이라도 있으면 정상 노화한다.
> 이 시나리오는 A가 남아 있으므로 트래커가 노화한다 → **부재 5초/30초/60초에서 각각 어떻게
> 되는지 관측해 기록**하는 것이 목적이다(PQ·PN 결정의 입력 자료).

## 3. 주의

- **이 시험 중 GPU 를 쓰는 다른 작업을 하지 말 것.** 소크 실측에서 GPU 공유 시 검출이 최대
  8초까지 밀렸다(`audit/soak_realcam_2026-08-17_report.md` 부록 A-3).
- 카메라 자체 지연이 약 1.4초 있다 — 화면에 보이는 것은 1.4초 전 장면이다. 동작과 화면을
  실시간 대조하지 말고 **기록 파일 기준으로 판정**한다.
- 실서비스 검출 캐던스는 **2.3fps**(0.43초 간격)다. 빠르게 지나치면 교차 순간이 1~2프레임에만
  잡힌다 — **천천히 걸을 것**.
