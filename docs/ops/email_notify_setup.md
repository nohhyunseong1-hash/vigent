# 이메일 알림 채널 설정 — Gmail 앱 비밀번호 (2026-09-22)

> **설정값은 대표가 직접 넣는다.** 이 문서는 절차만이며, 비밀번호는 **코드·채팅에 쓰지 않는다**(규칙 5).

## 0. 왜 두 번째 채널이 필요한가 — 실제 사고

**2026-08-21 22:04 을 마지막으로 텔레그램 봇 토큰이 무효(401)가 됐고, 2026-09-10 까지
20일간 경보 213건이 사람에게 닿지 않았다.** 그때 원격 채널은 **텔레그램 하나뿐**이었다.

| 항목 | 값 |
|---|---|
| 마지막 성공 전송 | 2026-08-21 22:04:41 |
| 이후 데드레터 | **213건** (401 포함 195건) |
| 설정돼 있던 원격 채널 | **텔레그램 1개** (이메일·웹훅 비어 있음) |

→ 채널이 하나면 그것이 죽는 순간 **경보가 아무에게도 가지 않는다.**
근거: `benchmarks/FINDINGS.md` F-35 · `audit/` 진단 기록.

★**전송 구조는 폴백이 아니라 동시 전송이다**(`dispatcher._dispatch_now`).
`on_severity` 에 `alarm`·`manager_call` 이 있는 등급(**critical·high**)은
텔레그램·이메일·웹훅에 **모두** 보낸다. 설정된 채널만 실제로 나간다.

| 등급 | 규칙 | 원격 전송 |
|---|---|---|
| **critical** | `fire_smoke` | ✅ 전 채널 |
| **high** | `zone_intrusion` · `ppe_missing` · `immobility` · `proximity_hazard` | ✅ 전 채널 |
| medium | `rapid_motion` 등 | ❌ 로그만(원격 없음) |

## 1. Gmail 앱 비밀번호 발급

⚠️ **일반 계정 비밀번호는 쓸 수 없다.** Google 이 2022 년부터 "보안 수준이 낮은 앱" 접근을
막았고, SMTP 는 **앱 비밀번호**를 써야 한다.

1. Google 계정 → **보안**
2. **2단계 인증을 먼저 켠다.** (켜지 않으면 앱 비밀번호 메뉴가 안 보인다)
3. 보안 → **앱 비밀번호** → 앱 이름에 `VIGENT` 입력 → 생성
4. **16자리 비밀번호**가 한 번만 보인다. 이 자리에서 복사한다(다시 못 본다).

★**이 16자리는 계정 비밀번호와 다르다.** 유출되면 그 앱만 차단하면 되므로 계정 비밀번호보다
안전하지만, 그래도 **메일 전체 접근 권한**이 있으니 취급은 비밀값 그대로다.

## 2. `config/notify.yaml` 에 넣기

```yaml
telegram_token: "…"          # 기존
telegram_chat: "…"           # 기존

smtp_host: "smtp.gmail.com"
smtp_port: 587               # STARTTLS
smtp_user: "보내는주소@gmail.com"
smtp_pass: "앱비밀번호16자리"     # ★공백 없이 붙여 쓴다(Google 이 4자리씩 띄어 보여준다)
email_to: "받는주소@example.com"  # 여러 명이면 쉼표로 구분
```

| 주의 | 내용 |
|---|---|
| `notify.yaml` | **`.gitignore` 대상**이다 — 커밋되지 않는다(규칙 5) |
| 앱 비밀번호 표기 | Google 은 `abcd efgh ijkl mnop` 처럼 보여준다. **공백을 빼고** 넣는다 |
| 포트 | 587(STARTTLS). 465(SSL)는 현재 코드가 쓰지 않는다 |
| 환경변수 대안 | `SMTP_HOST`·`SMTP_USER`·`SMTP_PASS`·`EMAIL_TO` 로도 된다(파일이 우선) |

## 3. 확인

서버를 재시작하지 않아도 된다 — 설정은 **매번 새로 읽는다**.

```bash
# 1) /health 로 채널 상태 확인
curl -s http://127.0.0.1:8010/health | python -m json.tool | grep -A 12 '"notify"'
```

기대값:

| 필드 | 기대 |
|---|---|
| `smtp_state` | `"ok"` (연결·STARTTLS 성공) |
| `remote_channel_count` | **2** 이상 |
| `single_channel` | **false** ← 이게 true 면 아직 채널이 하나뿐이다 |
| `selftest_state` | `"ok"` |

```bash
# 2) 실제 전송 시험
curl -s -X POST http://127.0.0.1:8010/alerts/test
```

메일이 오는지 **눈으로 확인한다.** 스팸함도 본다(첫 메일은 스팸으로 갈 수 있다).

## 4. 실패하면 어떻게 드러나는가

★**조용히 실패하지 않는다**(F-35 재발 방지, 2026-09-22 구현).

| 증상 | 어디에 드러나나 |
|---|---|
| 인증 오류(535 등) | **붉은 배너** "알림 채널 불능" + 로그 **CRITICAL** + `/health notify.config_error` |
| 연결 실패(망·방화벽) | `/health notify.smtp_state="unknown"` — 설정 오류로 **단정하지 않는다** |
| 채널이 하나뿐 | `/health notify.single_channel=true` |
| 하루 1회 점검 메시지 | `notify.heartbeat_at` 설정 시각에 옴. **안 오면 채널이 죽은 것** |

★SMTP 자가시험은 **연결까지만** 한다. 로그인은 하지 않는다 — 기동마다 인증을 시도하면
Gmail 이 반복 실패를 **계정 잠금**으로 볼 수 있다. 자격증명 오류는 실제 전송 때 드러난다.

## 5. 흔한 실패

| 증상 | 원인·조치 |
|---|---|
| `SMTPAuthenticationError 535` | 앱 비밀번호가 아니라 계정 비밀번호를 넣었거나, 공백이 섞였다 |
| 앱 비밀번호 메뉴가 없다 | **2단계 인증이 꺼져 있다.** 먼저 켠다 |
| `SMTPRecipientsRefused` | `email_to` 주소 오타 |
| 연결 타임아웃 | 현장 방화벽이 587 을 막았을 수 있다. 망 담당자에게 확인 |
| 메일이 안 보인다 | **스팸함 확인.** 발신 주소를 주소록에 추가하면 이후엔 정상 수신 |

## 6. 하지 않는 것

- **앱 비밀번호를 코드·문서·채팅에 쓰지 않는다**(규칙 5). `notify.yaml` 에만 둔다.
- 회사 공용 메일 계정을 쓰지 않는다 — 앱 비밀번호가 유출되면 메일 전체가 노출된다.
  **경보 전용 계정**을 따로 만드는 편이 안전하다.
