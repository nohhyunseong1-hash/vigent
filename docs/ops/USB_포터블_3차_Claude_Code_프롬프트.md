## 배경

2차 작업 결과: 1차 산출물 커밋, `vc_redist.x64.exe` 동봉 + 자가진단 분기, `VIGENT_데이터정리.bat` + `copy_to_usb.ps1` 실데이터 제외, 개발기 `.venv` torch 를 `2.12.0+cu130` 으로 복구(662 tests OK), `benchmarks/FINDINGS.md` F-33 추가(영향 문서 6개·16곳 "★재측정 필요(F-33)" 주석). `scripts/setup_env.py` 재발 방지 diff 는 F-33 에 수록만 하고 **미적용**. 미추적 파일 1개(`docs/ops/USB_포터블_후속_Claude_Code_프롬프트.md`).

노트북 2차 소크는 종료됐을 것이다(예정 21:05). **노트북에는 결과 파일을 읽는 것만 허용**하고, 서비스 재기동·설정 변경·파일 쓰기는 하지 마라.

## 작업 1 — setup_env.py 재발 방지 적용 (승인함)

F-33 에 수록한 diff 를 적용하라. 설계는 그대로: pip 설치 전에 **새 프로세스**로 `torch.version.cuda` 를 읽어 CUDA 빌드면 torch/torchvision 줄을 뺀 임시 requirements 로 설치하고, 설치 후 빌드가 바뀌었으면 비정상 종료(0 이 아닌 코드 + 한글 원인).

검증은 **세 상태** 모두 실측하라(2차에서 제안한 두 상태에 하나 추가):

| 상태 | 만드는 법 | 기대 결과 |
|---|---|---|
| A. cu130 설치됨(현재 개발기 .venv) | 그대로 | torch/torchvision 건너뜀, 경고 1줄, 종료 후 `2.12.0+cu130` 불변, `cuda.is_available()==True` |
| B. CPU torch 설치됨 | **개발기 .venv 를 건드리지 말고** 임시 venv(`%TEMP%\venv_cpu`, `py -3.11 -m venv`)에 PyPI torch 설치 | 기존과 동일하게 동작(CPU 빌드는 보호 대상이 아니므로 requirements 대로 설치), 종료 코드 0 |
| C. torch 미설치(새 환경 = 노트북 서비스 설치 경로) | 임시 venv(`%TEMP%\venv_new`) 빈 상태 | 기존과 완전히 동일하게 설치·검증(cv2 4.13 headless, 가중치 조달까지), 종료 코드 0 |

- 상태 A 에서 `.venv` 의 torch·numpy·cv2 버전이 실행 전후 동일함을 파일로 남겨라(`audit/setup_env_guard_<날짜>.txt`).
- 임시 venv 두 개는 검증 후 삭제하라.
- 상태 C 가 원본과 다르게 동작하면 **적용을 되돌리고** 원인을 보고하라 — 노트북 설치 경로가 깨지는 것이 이 수정의 유일한 위험이다.
- 커밋 1개. 2차 프롬프트 문서(`docs/ops/USB_포터블_후속_Claude_Code_프롬프트.md`)도 1차 문서와 일관되게 이 커밋에 넣어라.

## 작업 4 — 개발기 cu130 소크 재실행 → F-33 16곳 재측정

1. 9월 8일 드라이런·1h 소크가 **정확히 어떤 절차·스크립트·설정**으로 돌았는지 `git log --since=2026-09-07` 과 관련 문서에서 찾아 그대로 재현하라(`scripts/pilot_load_test.py` 또는 `soak_realcam.py`·`soak_report.py` — 어느 것이었는지 확인). 절차가 다르면 비교가 안 된다.
2. 실행 전 조건 기록: `torch.__version__ == 2.12.0+cu130`, `torch.cuda.is_available()==True`, `nvidia-smi` 드라이버·유휴 VRAM, 다른 GPU 프로세스 없음.
3. 소크 중 `nvidia-smi --query-gpu=memory.used,utilization.gpu --format=csv -l 10` 을 별도 파일로 기록해, **서버 몫 VRAM 차분**을 이번엔 실제 GPU 사용 상태로 재산출하라.
4. F-33 의 16곳을 재측정값으로 갱신하라. 형식: 기존 값은 지우지 말고 `구값(CPU, F-33 무효) → 신값(cu130, <날짜>)` 으로 병기. 재측정 불가 항목은 이유를 적고 "★재측정 필요(F-33)" 를 남겨라.
5. 신값으로 P1-10 을 "확정 해소" 로 바꿀 수 있는지 판정하고, 판정 근거를 F-33 에 적어라. 바꿀 수 없으면 바꾸지 마라.
6. 커밋 1개.

## 작업 5 — 실제 USB 복사 + 제3 PC 실기동 체크리스트 (문서만)

USB 는 **삼성 64GB USB 메모리**를 쓴다. 사람이 손으로 할 절차를 만든다.

1. `deploy/portable/USB_실기동_체크리스트.md` 를 작성하라. 개발 지식 없는 사람이 따라 할 수 있게, 명령은 한 줄씩. 내용:
   - **준비**: USB 를 개발기에 꽂고 드라이브 문자 확인 → 파일 시스템 확인(`Get-Volume`). exFAT 이면 그대로, FAT32 면 exFAT 로 포맷(포맷은 USB 안 내용을 지운다는 경고 포함). NTFS 는 쓰지 않는다.
   - **복사**: `scripts\copy_to_usb.ps1 -Drive <문자>:` 실행 → 스크립트가 출력하는 파일 수·바이트가 `46,746 / 2,606,144,265`(2차 실측) 와 일치하는지 확인 칸.
   - **개발기 자체 검증**: USB 에서 직접 `VIGENT_시작.bat` 실행(`subst` 가 아니라 **실제 USB**) → 첫 기동까지 초시계 시간, `/health` 200, 슬롯 3개 LOADED, `/home` 열림 → `VIGENT_종료.bat` → `VIGENT_데이터정리.bat`. 기록 칸: 첫 기동 시간(초), 두 번째 기동 시간(초).
   - **제3 PC 실기동**(개발기·현장 노트북이 아닌 Windows 10/11 PC, 파이썬 미설치 PC 우선): 꽂기 → 탐색기에서 `VIGENT_시작.bat` 더블클릭 → SmartScreen 이 뜨면 "추가 정보 → 실행" → VC++ 안내가 뜨면 `vc_redist.x64.exe` 설치 후 재실행 → 브라우저 `/home` → 웹캠 1대 등록·타일 ON → 사람이 카메라 앞에 서서 person 박스 확인 → `VIGENT_종료.bat` → `VIGENT_데이터정리.bat`. 기록 칸: PC 사양(CPU/RAM/OS 에디션/파이썬 유무), 첫 기동 시간, SmartScreen 여부, VC++ 안내 여부, 검출 확인, 오류 메시지 원문.
   - **합격 기준**(미리 선언): 첫 기동 ≤ 3분, `/health` ok, person 검출 1회 이상, 종료 후 잔존 프로세스 0. 기동이 3분을 넘기면 "불합격 아님 · USB SSD 로 매체 교체 검토" 로 분류.
   - **주의**: 시험 후 USB 안 `app\data` 에 사람 얼굴 사진이 남을 수 있으므로 정리 스크립트를 반드시 실행. USB 를 타인에게 건네지 않는다.
2. 체크리스트에 실제 USB 를 꽂아야 하는 단계가 있으므로 Claude Code 는 **실행하지 말고 문서만** 만들어라. 단, `copy_to_usb.ps1` 이 exFAT 드라이브에서 `robocopy` 타임스탬프 정밀도(exFAT 2초 단위) 때문에 검증 단계에서 오탐하지 않는지 코드로 확인하고, 문제가 있으면 `/FFT` 옵션 등으로 고쳐라.
3. 커밋 1개.
