# VIGENT 인프라 조달 사양서 (GPU·카메라·데이터)

> 목적: 파일럿·상용을 위한 **GPU 장비·카메라 구매 결정**의 근거 자료. **자체 실측치**에 기반하며,
> 측정하지 않은 값(예: 특정 GPU의 처리량)은 **"미측정·벤치 필요"** 로 명시한다(규칙7 — 지어내지 않음).

---

## 1. 처리 장비(GPU) 요구사항

### 1.1 왜 GPU가 필요한가 — 현재 개발환경(Apple MPS)의 실측 한계
현재 개발은 Apple Silicon(MPS)에서 하며, 아래 한계가 **실측**되었다:

| 실측 한계 | 수치·근거 |
|---|---|
| **위험구역 타일링이 CPU에서 느림** | 프레임당 **+415ms**(CPU). 다중카메라 실시간 불가.[^tile] |
| **MPS 다모델 동시추론 크래시(F-14)** | 여러 추론 엔진 동시 사용 시 네이티브 크래시 이력. 이번에 근본 해소했으나, **다중 프로세스 MPS는 여전히 악화요인**.[^f14] |
| **부하 시 워커 정지(hang)** | 소크 시험 중 MPS 검출 지연 + 15s hang 임계로 백그라운드 워커가 간헐 정지·재기동. 검출이 느려서 생기는 문제.[^soak] |
| **MPS에서 학습 불가** | 재학습(fine-tune)이 MPS matcher 메모리 오염으로 불가 → **CUDA 필수**.[^train] |
| **모델 콜드 로드 ~250s** | RF-DETR 초기 로드가 수분(운영엔 상주 프로세스로 흡수, 단 GPU 웜업 고려).[^load] |

→ **결론: 다중카메라 실시간·재학습에는 NVIDIA CUDA GPU가 필요**하다. MPS는 개발·단일카메라 데모용.

### 1.2 사양(요구 기준) — ⚠️ GPU 처리량은 미측정, 후보 장비에서 벤치 필요
> **정직 고지**: 우리는 아직 **NVIDIA GPU에서 카메라당 FPS·동시 카메라 수를 측정하지 않았다.** 아래는
> "무엇이 필요한지"의 요구 기준이며, **실제 카메라 수용량은 후보 장비 1대를 빌려 벤치마크한 뒤 확정**한다.

| 구분 | 최소 | 권장 | 비고 |
|---|---|---|---|
| **GPU** | NVIDIA CUDA **VRAM ≥ 4GB** | VRAM 6GB | ★[V1, 2026-08-19 하향] **GPU 는 병목이 아니다** — 8대에서도 util **최대 42%**. VIGENT 단독 VRAM 실측 **1.4GB**(현행 3슬롯), 카메라당 +5 MiB. ★구 표기 "3.2GB"는 **GPU 총량 오독**이었다(Windows 데스크톱·VS Code 등 포함) → **GTX 1650(4GB)급이면 충분**. **비싼 GPU 는 낭비다** |
| **동시 카메라** | 1대 | **권장 5대**(한계 7대) | ★[C5, 2026-08-18] Ryzen 9 9900X + RTX 5070 Ti 실측 — `benchmarks/capacity_report.md`. 8대에서 검출 p95 116→309ms 붕괴. 다른 사양은 재측정 필요 |
| **CPU** | **카메라당 2.03 환산코어 @2fps**(GPU 있음)<br>**4.43**(GPU 없음) | 한계 N = 환산코어 × 0.70 ÷ 2.03 | ★[E1] **여기가 병목이다.** "환산코어" = 기준 CPU(Ryzen 9 9900X, PassMark ST 4,672 / Mark 54,322) 코어 환산 — 계산법은 [`edgebox_purchase_guide.md`](edgebox_purchase_guide.md) §2 |
| **RAM** | 16GB | 32GB | 소크 실측 RSS ≈ 3.2GB + OS·torch |
| **저장** | SSD 256GB | NVMe 500GB | ★실사용 실측 **≈5.2GB**(site-packages 4.09 + 저장소 0.66 + 가중치 0.35 + 증거 30일 5대 0.1) — **병목 아님** |
| **OS** | **Windows 10/11** | 동일 | ★현재 배포 경로가 Windows 의존(NSSM 서비스·`cipher /c`·BitLocker 검사·PowerShell). Linux 이식은 가능하나 **미검증** |

### 1.3 후보 폼팩터(트레이드오프) — ★[E1, 2026-08-18] 실측으로 갱신

**구매 실무(사양표·체크리스트·인수시험)는 [`docs/edgebox_purchase_guide.md`](edgebox_purchase_guide.md) 로 분리했다.**

| 폼팩터 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **엣지 박스**(Jetson Orin 등) | 저전력·팬리스 | **Windows 불가** → 위 §1.2 의존 4가지가 깨진다. ARM 용 torch·RF-DETR **미검증** | ❌ **현재 부적합** |
| **미니PC + NVIDIA GPU** | 성능/비용 균형·확장 용이 | 전원·발열·설치 공간 | ✅ **기본 경로** |
| **랙 서버(GPU)** | 다중 카메라·재학습 겸용 | 비용·상면·냉각 | 다현장·중앙 처리 |

- **예산을 CPU 에 쓸 것**: 병목이 CPU(추론 전·후처리)다. GPU 는 VRAM 6~8GB 최저가 CUDA 카드로 충분하다.
- **NVDEC·하드웨어 디코딩에 돈을 쓰지 말 것**: 디코드는 프레임당 **0.4~1.2ms** 로 병목이 아니다(E1 §1 H1 기각).
- **파일럿 권장**: 미니PC + NVIDIA GPU 1대. **30~50만원 예산에서 확실한 것은 카메라 1~2대**이며,
  4~5대는 이 예산에서 **보증 불가**다 — 필요 환산코어 15~20(= PassMark CPU Mark 27,000~45,000)은
  이 예산대 중고 사무용 CPU(Mark 9,500~16,000) 범위 밖이다(`edgebox_purchase_guide.md` §3-B·§4·§10).
- **구매 후 반드시** `scripts/capacity_probe.py` 로 그 박스의 대수를 재측정한 뒤에 대수를 약속한다.
- **재학습**: 온프렘 상시 필요 없음 → **클라우드 GPU(스팟) 임대**로 배치 학습이 비용효율적(MPS 학습 불가 회피).[^train]

## 2. 카메라 요구사항

### 2.1 광역 CCTV로 가능한 기능 vs 근접 카메라가 필요한 기능

| 기능 | 광역 CCTV | 근접 카메라 | 근거 |
|---|---|---|---|
| **위험구역 침입**(파일럿 주력) | ✅ 가능(소형작업자는 타일링 on) | 불필요 | 타일로 recall 0→89~95% 실측[^tile] |
| **화재/연기** | ✅ 가능(공개셋 mAP@50 80%) | — | 현장 미검증[^fire] |
| **보호구 미착용** | △ 제한적(원거리 안전모 놓침) | 유리 | NO-Hardhat R56, 재학습 대기[^ppe] |
| **낙상/쓰러짐** | **기능 제거됨(2026-08)** | — | 오탐 지속·참조 클립 부재로 제거(PF). 제거 전 실측으로는 광역 CCTV(26~64px)에서 pose 산출 3.9%로 애초 판별 불가했음[^fall] |
| **지게차 협착** | △ 검출기 비활성(재학습 대기) | — | F-7 오탐[^ppe] |

### 2.2 근접 카메라 최소 스펙(자세 기반 기능용 — 부담자세 등) — B8 실측 산출(낙상 검증 중 확보한 수치)
- **작업자 최소 픽셀 높이 ≥ 120px**(현재 광역은 26~64px). 포즈(RTMPose)가 안정적으로 keypoint를 내는 하한 경험칙(61px median에서 pose 산출 3.9% → 최소 2배 필요).[^fall]
- **역산 가이드(초안, 실측 보정 전제)**: 작업자 실키 ~1.7m를 120px로 담으려면 세로 픽셀밀도 ≈ **70px/m 이상**. → **1080p면 세로 실시야 ≤ ~15m, 720p면 ≤ ~10m** 안에 작업역이 들어오도록 설치 거리·초점거리(화각)를 잡는다.[^fall]
- → 광역 조망용이 아니라 **작업역 전용 근접 카메라(별도 채널)**. 부담자세 등 자세 기반 판정의 정확도를 높이려면 이 스펙을 조달 조건에 포함(낙상 기능은 2026-08 제거됨 — 재도입 시에도 동일 스펙 필요, PF 참고).
- 공통: **RTSP 지원**, 야간·역광 대비(현장 조명 조건 실측 필요).

## 3. 데이터 수집 요건 (재학습·검증)

> **왜 필요한가**: 현재 커스텀 검출의 약점은 **현장 데이터 부족**에서 온다. 아래 데이터가 확보되면 이미 만든
> 재학습 스크립트(`tools/train_safety.py`·`train_merged.py`)로 진행하고, 검증은 골든 회귀·추적 A/B·소크로 한다.

### 3.1 재학습용(모델 정확도 개선)
| 대상 | 필요 데이터 | 근거·목표 |
|---|---|---|
| **안전모 미착용** | 미착용 장면 다양(현장·각도·조명) 라벨 | NO-Hardhat R56(≈44% 놓침) 개선[^ppe] |
| **지게차** | 지게차 다양 각도·거리 라벨 | 현재 정탐 conf 0.002(오탐과 겹침)=비활성. PoC로 box mAP **8.83→58.62%** 개선 실증했으나 **full 재학습 필요**(비활성 해제 전제)[^forklift] |
| (학습 컴퓨트) | — | **MPS 학습 불가 → 클라우드 CUDA**[^train] |

### 3.2 검증용(측정≠배포 리스크 해소)
| 목적 | 필요 데이터 | 근거 |
|---|---|---|
| **낙상 재도입 검증**(현재 기능 제거 상태, PF) | 광역 CCTV 낙상/깔림 **사고 영상 ≥ 10건**(서로 다른 현장·시간대·조명) + 정상 작업 **≥ 3시간**(오탐율 분모) | 2026-08 기능 제거(오탐 지속·참조 클립 부재). 재도입하려면 이 데이터로 recall·오탐율을 신뢰구간과 함께 산출 필요[^fall] |
| **추적 품질 정식 지표(MOTA/IDF1)** | 다인 현장 클립 + **트랙ID GT 라벨** | 현재 프록시 지표뿐(P3 B10). ByteTrack 우위 정식 재확인[^track] |
| **현장 오탐율(zone_intrusion)** | 실카메라 정상 작업 수 시간 | 타일 현장 오탐 **미실측**(최대 블로커)[^tile] |
| **24h 실카메라 안정성** | 실 RTSP 24h 연속 | 현재 90분 합성만 합격. 실카메라 미실행[^soak] |

### 근거(각주)
[^tile]: 위험구역 타일링 recall 0%→89~95%(크레인 실사고 영상 실측), 타일 +415ms/f(CPU). `docs/COMMERCIALIZATION_READINESS.md` §1·블로커4, `docs/P3_BACKLOG.md` B9, `docs/ONBOARDING.md` §2.3. **현장 오탐율 미실측**.
[^f14]: 동시부하 네이티브 크래시(F-14) 근본 해소 — VLM 전용 고정 스레드. 커밋 `fd606c1`, `benchmarks/FINDINGS.md` F-14. 다중 MPS 프로세스는 악화요인(실측).
[^soak]: 24h 소크 감시 도구·90분 합성 검증 합격(`audit/soakmon_2026-07-20_validate90m.md`, 커밋 `4509dbb`). 부하 하 MPS 워커 hang은 이번 소크 실측 소견. **실카메라 24h 미실행**.
[^train]: MPS matcher 메모리 오염으로 학습 불가 → CUDA 필수. `benchmarks/FINDINGS.md`(forklift), 프로젝트 메모리(forklift PoC). 재학습은 클라우드 CUDA 권장.
[^load]: RF-DETR 콜드 로드 ~250s 관측(이번 세션 서버 기동·측정 로그). 운영은 상주 프로세스로 흡수.
[^fire]: fire_smoke 공개셋 D-Fire mAP@50 80.13%. `docs/COMMERCIALIZATION_READINESS.md` §1. **현장 미검증**.
[^ppe]: PPE 공개셋 착용 R67~76·미착용 NO-Hardhat R56.1. forklift 비활성(F-7, 정탐 conf 0.002). `docs/COMMERCIALIZATION_READINESS.md` §1. **현장 미검증·재학습 대기**.
[^fall]: 2026-08-06 작업자 낙상 감지 기능 제거(오탐 지속·참조 클립 부재, `docs/P3_BACKLOG.md` PF). 제거 전 실측: 광역 CCTV 낙상 자동판별 불가(작업자 26~64px, pose 산출 3.9%). 근접 카메라 요구: 최소 120px·~70px/m·1080p≤15m·720p≤10m. 재개 조건: 사고영상 ≥10건 + 정상 ≥3시간. 같은 문서 B8. (역산은 초안, 실측 보정 전제.)
[^forklift]: forklift 병합데이터 PoC box mAP 8.83→58.62% 실증(그러나 full 재학습·배포 복원 전 비활성). `docs/COMMERCIALIZATION_READINESS.md` §1(proximity), 프로젝트 메모리(forklift PoC).
[^track]: 추적기 A/B(크레인 400f): SORT 39ID·13스위치 → ByteTrack 5ID·0스위치. `tools/track_quality.py`, 커밋 `43e60b8`·`c4a13fd`. 정식 MOTA/IDF1은 라벨 확보 후(P3 B10).
