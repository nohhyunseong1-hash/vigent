# VIGENT 팀 협업 기획안 제작 (3단계: 실태 감사 → 문서화 → PDF 배포본)

너는 **기술 감사관 → 신입 온보딩 문서 작성자 → 편집 디자이너** 역할을 순서대로 맡는다.

독자는 **바이브코딩도 팀 프로젝트도 처음인 팀원 전원(대표 포함)**이다.
"터미널이 뭔지 모르는 사람"이 이 문서만 읽고 **첫 커밋까지 스스로 도달**해야 한다. 이것이 문서 품질의 유일한 판정 기준이다.

---

## 0. 절대 원칙 (전 단계 공통)

1. **숫자는 창작 금지.** 모든 성능·개수·날짜는 리포 내 실제 파일(벤치 결과, 로그, 테스트 출력, git 이력)에서만 인용한다. 각 숫자 옆에 **출처 파일 경로 + 확인 명령어**를 반드시 병기한다.
2. 근거를 못 찾은 항목은 추정하지 말고 **`[측정 필요]`** 로 표기하고, "무슨 명령을 돌리면 알 수 있는지"를 한 줄로 적는다.
3. **Phase 1에서는 코드를 절대 수정하지 않는다.** 읽기·조회 명령만 사용. 마지막에 `git status`로 무변경을 확인한다.
4. 한국어로 쓴다. 전문 용어는 **첫 등장 시 괄호로 쉬운 설명**을 붙인다. 예: `커밋(commit, 작업 내용을 저장하는 것)`
5. **특허 보호**: RIG 모듈 상태기계의 전이 조건·임계값 등 세부 메커니즘은 팀 문서에도 개요 수준만 쓰고, 상세는 `[대외비 — 별도 문서]`로 표기한다.
6. 잘 되는 것과 **안 되는 것 / 미구현**을 같은 비중으로 쓴다. 팀원이 착각하면 일정이 무너진다.
7. **개발 도구는 Claude Code 하나로 통일한다.** 다른 IDE·플러그인·에이전트 도입을 제안하지 말 것. 모든 작업 지시는 "Claude Code에 붙여넣을 문장" 형태로 제시한다.
8. 문서는 **한 개씩** 만들고, 각 파일 완료 시 한 줄로 보고한 뒤 다음으로 넘어간다.

# Phase 1 — 실태 감사 (문서 작성 전, 표로 먼저 보고)

리포 전체를 훑고 아래 표 4개를 **화면에 출력**한다. 아직 파일은 만들지 않는다.

### 표 1-A. 비전(L1) 현황
공통 열: `항목 | 현재 수치 | 출처 파일 경로 | 확인 명령어 | 상태`

- 탐지 클래스별(person / PPE / fire·smoke / forklift) 최신 확정 지표: **mAP, F1, 추론 지연(ms)**, 측정 환경(GPU·해상도·배치 크기)
- 클래스별 가중치 파일의 실제 존재 여부, 경로, 파일 크기, 최종 수정일
- KISA 기준(F1 ≥ 0.90) 대비 **클래스별 갭을 숫자로**
- 포즈 추정(RTMPose)·추적 연동 여부, 파이프라인 진입점 파일 경로
- 라이선스 스캔 결과 (AGPL 잔존 건수 — 0이어야 함)
- 안정성: 스트림 재연결 로직 / 전역 예외처리·워치독 / 연속 구동 테스트 기록 유무
- 미해결 항목: 현장 도메인 갭, 재학습 대기, 엣지(RK3588) 포팅 등

### 표 1-B. 에이전트(L2) 현황
- 6개 에이전트(Dispatcher / Guard / Analyst / Scribe / Coach / Copilot) **각각**의 파일 경로 + 구현 상태(완료 / 부분 / 스텁) + 코드 줄 수 (단서 2026-09-26: 현재 `agents/` 는 Coach 없이 7파일(+SafetyManager). 별도 L2 저장소의 LangGraph 6노드는 설계·부분 구현 단계 — 미실행·모델 실행 기록 0·L1 브리지 미구현. `docs/review/ALGORITHM_TRUTH_20260926.md` §3)
- 골든셋: 작성 건수 / 목표 건수, 최근 채점 점수(축별 점수 포함)
- 법령 화이트리스트: 조문 개수, 파일 경로, 검수 이력
- 문서 생성기: 지원하는 산출물 종류 / 미구현 종류
- 환각 차단 로직의 위치와 실제 동작 여부, 차단 로그가 남는지
- 테스트: 테스트 파일 개수, **실제로 `pytest`를 실행**한 통과/실패 개수
- **L1 → L2 연동**(감지 이벤트가 체크리스트로 흐르는 경로)의 실제 연결 여부
- 사전 식별된 갭(G1~G3 등)이 코드에 남아 있는지 실확인

### 표 1-C. RIG 모듈 현황
- 상태기계 구현 파일 경로, 단위 테스트 개수와 통과 수, 실영상 검증 범위
- 하드웨어(LED·부저)·음성 등 설계 단계 항목을 구현분과 명확히 구분

### 표 1-D. 리포·협업 인프라 현황
- 총 커밋 수(`git log --oneline | wc -l`), 최근 커밋 10건 요약
- 브랜치 목록과 분기 상태, 미커밋 변경 존재 여부
- README / CLAUDE.md / .gitignore / requirements 버전 고정 여부
- **신규 팀원이 합류했을 때 막힐 지점** 목록 (.env 없음, 모델 가중치가 git에 없음, 설치 문서 없음, 실행 진입점 불명확 등)

> **→ 여기서 멈추고 사용자 확인을 기다린다.** "Phase 2 진행"이라는 답을 받기 전에는 어떤 파일도 만들지 않는다.

## `50_완전초보_온보딩.md` — 가장 자세하게 쓸 것
독자의 컴퓨터에 아무것도 안 깔린 상태를 가정한다. **macOS와 Windows를 각각 나눠서** 쓴다.

1. 터미널 여는 법 (macOS: Spotlight → "터미널" / Windows: PowerShell) — **실제 눌러야 할 키까지**
2. 내가 어느 폴더에 있는지 확인(`pwd`), 이동(`cd`), 목록 보기(`ls` / `dir`)
3. Git 설치 확인·설치 방법, 최초 1회 설정(`git config --global user.name / user.email`)
4. Python 버전 확인, 가상환경 생성·활성화, 의존성 설치
5. 리포 내려받기(`git clone`) — 주소 자리는 `<여기에 저장소 주소>`로 표기
6. Claude Code 설치·실행법, 프로젝트 폴더에서 `claude` 치는 것까지
7. **첫 실행 성공 확인**: 어떤 명령을 쳤을 때 무엇이 보이면 성공인지 구체적으로
8. **자주 나는 에러 5가지와 대처법** (권한 오류 / 명령어 못 찾음 / 포트 사용 중 / 가상환경 미활성 / 모델 가중치 없음)
9. 막혔을 때 행동 순서: ① 에러 메시지 전체 복사 ② Claude Code에 "이 에러가 났어" + 붙여넣기 ③ 그래도 안 되면 팀 채널에 에러 전문 공유

- **깃이 뭔지 비유로 설명** (게임 세이브 파일 / 문서 버전 관리)

- 하루 작업 흐름을 명령어 순서대로, **각 줄마다 "이 명령이 하는 일" 한 줄 해설**:

```
git pull                          (최신 내용 받기)
git checkout -b feat/내작업이름     (내 작업 공간 만들기)
... 작업 ...
git status                        (뭐가 바뀌었는지 보기)
git add -A
git commit -m "feat: 무엇을 했는지"
git push -u origin feat/내작업이름
```

- 브랜치 이름 규칙, 커밋 메시지 규칙(feat / fix / docs / test + 한글 설명), **예시 5개**

- 충돌(conflict) 발생 시 초보자 대처: 당황하지 말고 → 아무것도 저장하지 말고 → 상황 그대로 Claude Code에 붙여넣기
- **git에 올리면 안 되는 것**: `.env`, API 키, 모델 가중치, 현장 영상·개인정보 포함 파일
- 코드 리뷰: PR 올리는 법, 리뷰어 지정, **승인 없이 merge 금지**

# Phase 3 — PDF 배포본 생성

## 만들 PDF 4종 (`docs/team/pdf/`)
1. `VIGENT_기획안_통합본_v1_YYYYMMDD.pdf` — 00~80 전체
2. `VIGENT_비전트랙_v1_YYYYMMDD.pdf` — 00, 01, 10
3. `VIGENT_에이전트트랙_v1_YYYYMMDD.pdf` — 00, 01, 20
4. `VIGENT_신규팀원_온보딩_v1_YYYYMMDD.pdf` — 00, 40, 50, 60, 70, 80

## 한글 깨짐 방지 (필수)
PDF 변환에서 가장 흔한 실패는 **한글이 네모(□□□)로 나오는 것**이다. 반드시 아래 순서로 시도하고, 각 시도의 성공/실패를 보고하라.

- **1순위**: Markdown → 단일 HTML(스타일 인라인 포함) → 헤드리스 브라우저로 PDF 변환
  - CSS `font-family` 우선순위: `'Pretendard', 'Noto Sans KR', 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`
- **2순위**: 시스템에 이미 설치된 변환 도구 사용 (설치되어 있는 것만 쓸 것. 없으면 설치 시도하지 말고 다음으로)
- **3순위(항상 보장)**: 스타일이 적용된 HTML 파일만 생성하고, **"브라우저로 열어 Cmd/Ctrl+P → PDF로 저장"** 안내문을 `docs/team/pdf/README.md`에 적는다

**변환 후 반드시 검증**: 생성된 PDF에서 텍스트 추출을 시도해 한글이 정상인지 확인하고 결과를 보고한다. 깨졌으면 3순위로 내려간다.

## PDF 편집 규격
- A4 세로, 여백 20mm, 본문 10.5pt, 줄간격 1.6
- **표지 1장**: 문서명 / 버전 / 생성일 / `대외비 — 외부 배포 금지`
- 표지 다음 **목차**(페이지 번호 포함)
- 머리말에 문서명, 바닥글에 `페이지 N / 총 M`
- 표는 페이지 중간에서 잘리지 않게, 코드 블록은 회색 배경 + 줄바꿈 허용
- 신호등(🟢🟡🔴)이 PDF에서 안 보이면 `[완료] [진행중] [미착수]` 텍스트 병기
- 모든 페이지 하단에 `VIGENT 대외비` 문구
