# 포터블의 CRT(vcruntime/msvcp) 로드 경로 실측과 두 안 비교 (I-4, 2026-09-23)

> **성격**: 실측 + 권고. **구현하지 않았다.** 결정 뒤에 한다.

---

## 1. 무엇을 쟀나

`torch` 를 import 하고 CUDA 컨텍스트를 만든 **뒤** 프로세스에 실제로 로드된 CRT DLL 의
전체 경로와 파일 버전을 읽었다([`scripts/bench/loaded_crt.py`](../../scripts/bench/loaded_crt.py)).
설정이나 문서가 아니라 **프로세스 모듈 목록**이 근거다.

대상: `D:\vigent_portable_gpu` (torch 2.12.0+cu130, `cuda_available=True`)

## 2. 실측 결과

| DLL | 버전 | **어디서 로드됐나** |
|---|---|---|
| `vcruntime140.dll` | **14.38.33126.1** | ★**동봉본** `…\python\VCRUNTIME140.dll` |
| `vcruntime140_1.dll` | **14.38.33126.1** | ★**동봉본** `…\python\VCRUNTIME140_1.dll` |
| `msvcp140.dll` | 14.51.36247.0 | 시스템 `C:\WINDOWS\SYSTEM32\msvcp140.dll` |
| `msvcp140_atomic_wait.dll` | 14.51.36247.0 | 시스템 `C:\WINDOWS\SYSTEM32\…` |
| `msvcp140_1.dll` · `concrt140.dll` | — | 로드 안 됨 |

★`vcruntime140.dll` 은 **torch import 전에 이미** 로드돼 있다 — CPython 자신이 쓴다.

### 그래서 지금 상태는 "섞여 있다"

- `vcruntime` 계열 = **14.38**(동봉본, python.exe 옆이라 System32보다 먼저 찾는다)
- `msvcp` 계열 = **14.51**(동봉 안 돼 있어 시스템 재배포에서)

Microsoft 규칙(*C++ binary compatibility 2015-2026*)은 **"재배포 버전은 구성요소 중 최신
빌드툴 이상"** 이어야 한다고 말한다. 포터블 구성요소의 빌드툴 최댓값은 **14.44**(torch/cuDNN,
PE 링커 버전 실측)이고 전체로는 14.51 이다.
→ **로드된 `vcruntime` 14.38 은 그 하한보다 낮다.**

### 지금 당장 깨지나 — 모른다

개발기에서는 **동작한다**(4채널 소크 35분 정상). 14.38 에 없는 export 를 요구하는 구성요소가
있었다면 import 시점에 죽었을 것이므로, 적어도 현재 구성에서는 문제가 드러나지 않았다.
위험은 **미래형**이다: torch·cuDNN·확장모듈을 올리면 어느 날 `프로시저를 찾을 수 없습니다`
로 죽는다. 그리고 그때 원인이 CRT 라는 걸 알아내기가 아주 어렵다.

## 3. 두 안 비교

| | **(a) 동봉본을 최신으로 교체** | **(b) 동봉 제거 → 시스템 재배포에 맡김** |
|---|---|---|
| 하는 일 | 빌드 때 `vc_redist.x64.exe` 에서 `vcruntime140(_1).dll` 을 뽑아 `python\` 에 덮어씀 | `python\vcruntime140*.dll` 을 지움 → System32 것이 쓰임 |
| CRT 일관성 | 동봉 14.5x + 시스템 14.51 — **거의 일치** | **완전히 한 벌**(전부 System32) |
| 재배포 없는 PC | **python.exe 가 뜬다** (CPython 이 동봉본으로 기동) | ★**python.exe 자체가 안 뜬다** — Windows 오류창만 뜨고 우리 안내문은 못 보여준다 |
| preflight 와의 관계 | 보조 안전망이 남는다 | **preflight 통과가 전제 조건이 된다**(우회하면 바로 깨짐) |
| 버전 관리 | 빌드마다 동봉본 버전을 따라가야 함(새 관리 대상) | 관리 대상이 **하나 줄어든다** |
| 패키지 크기 | ±0 (수백 KB) | −약 0.2 MB |
| 되돌리기 | 쉬움 | 쉬움 |

### 권고: **(a) 동봉본 최신 교체**

이유는 **실패 모드의 질**이다.
(b)는 "재배포가 없거나 낮은 PC"에서 **python.exe 가 뜨기도 전에** 죽는다. 그러면
preflight 도, 우리가 정성껏 쓴 한국어 안내문도 못 보여주고, 현장에서는
"USB 꽂았는데 아무 일도 안 일어남"이 된다. 이건 이 프로젝트가 계속 싸워 온
**조용한 실패**와 같은 모양이다.
(a)는 그 안전망을 유지하면서 버전 불일치만 없앤다.

**단서 두 가지**
1. 동봉본은 **`vc_redist.x64.exe` 에서 추출**한다. 빌드 기계의 System32 를 복사하지 않는다
   (기계마다 달라지면 패키지가 재현 불가능해진다).
2. 교체 후 `loaded_crt.py` 를 **다시 돌려** 로드 경로·버전이 바뀌었는지 확인한다.
   설치했다는 사실이 로드됐다는 증거는 아니다.

## 4. 아직 모르는 것

- **14.38 로 실제 문제가 나는 구성요소가 있는지 확인하지 못했다.** 현재 구성에서는 안 난다.
- 현장 노트북·파일럿기에서의 로드 경로는 **안 쟀다**(개발기 1대 결과다).
- `vc_redist.x64.exe` 에서 DLL 을 추출하는 절차는 **아직 안 만들었다**(결정 후).
