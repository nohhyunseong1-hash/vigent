## 3. 분량 — CVAT 트랙 라벨링 (2026-09-22 갱신)

★**라벨링 방식이 바뀌었다.** 프레임을 잘라 한 장씩 그리는 것이 아니라, **CVAT 에 원본 영상을
그대로 올리고 Track 모드로 키프레임만 찍는다.** 사이는 CVAT 이 선형 보간한다.
절차: `docs/labeling/cvat_setup.md` · 변환: `scripts/eval/cvat_to_gt.py`

| 항목 | 값 |
|---|---|
| 촬영 | 45분 |
| 버스트 정의 | **연속 5초** 구간 |
| 버스트 수 | **12개** (T1~T4 각 2 = 8, 기존 R1·R2·R3·R4 각 1 = 4) |
| 2fps 환산 프레임 | 12 × 10 = **120장** (평가에 쓰는 단위) |
| **사람이 찍는 키프레임(추정)** | **약 180~300개** (아래 근거) |

### 키프레임 추정 근거 — ★추정이다, 실측 전이다

CVAT 은 키프레임 사이를 **선형 보간**하므로, 사람은 **움직임이 꺾이는 지점**만 찍으면 된다.

| 장면 성격 | 트랙 수(추정) | 트랙당 키프레임(추정) | 버스트당 |
|---|---|---|---|
| 단순 통과(T1·T2) | 1~2 | 3~4 (시작·중간·끝) | 3~8 |
| 가림·재등장(T3) | 1~2 | 5~6 (가림 전·후를 각각) | 5~12 |
| 혼잡(R1·R3·R4) | 3~4 | 4~5 | 12~20 |
| 사람 없음(T4) | 0 | 0 | 0 |

12 버스트 × 평균 15~25 = **180~300 키프레임**. 프레임 120장을 전수로 그리는 것보다
**손이 덜 가지만, 트랙을 잇는 판단은 사람이 해야 한다**(그것이 IDSW 정답이다).

⚠️ **이 값은 추정이다.** CVAT 설치 후 **버스트 1개로 파일럿**을 재서 이 표를 갱신한다(규칙 7·9).
1차 라벨링 파일럿(`D:igent_field\labeling_pilot_20260829\`)도 **아직 미측정**으로 남아 있다.

### 2fps 샘플링 시점

★**촬영·업로드는 원 fps 그대로.** 2fps 추림은 **라벨을 마친 뒤 변환 단계**에서 한다
(`cvat_to_gt.py --fps 2`). 이유: CVAT 의 트랙 보간이 원본 프레임 위에서 동작해야
키프레임 사이가 정확하게 채워진다. 먼저 2fps 로 잘라 올리면 보간 근거가 성겨진다.

버스트 선정 기준(우선순위 순)
1. R-2 의 **D(트랙 종료)·A(확정 지연)** 가 재현된 구간
2. C-3 의 **세로 박스 패턴**이 나타난 구간
3. person_count 분포가 고르게(0~1명 / 2~3명 / 4명 이상)
4. 촬영 전체에 분산

★**촬영 전에는 고를 수 없다.** 수집 후 `track_debug.jsonl` 로 1·2 를 찾아 고른다.

## 4. ★검증 게이트 — 이것을 통과하기 전에 철수하지 않는다

절차서에 **다음 문장을 그대로 넣는다.**

> **장면이 끝날 때마다** 그 장면 폴더에 대해 아래를 돌린다. 통과하지 못하면 **그 장면을 다시 찍는다.**
> ```
> python scripts/check_raw_capture.py runs/field_<날짜>/<장면>
> ```
> **철수 직전** 전체를 한 번 더 돌린다. **전 장면이 통과하기 전에는 현장을 떠나지 않는다.**
> ```
> python scripts/check_raw_capture.py runs/field_<날짜>
> ```

`check_raw_capture.py` 가 보는 것(이미 구현돼 있음)
- `original.mp4` 존재·크기·**실제로 열려서 프레임이 나오는지**
- `raw/still_*.jpg` 존재 · 오버레이 스틸과 **개수 일치**
- `dets.jsonl` 존재·비어 있지 않음
- `dets` 행 수와 원본 프레임 수의 어긋남 경고

★**적어 두는 것과 만드는 것은 다르다.** 1차 절차서에도 "녹화 회수(필수)"라고 적혀 있었으나
확인하는 장치가 없어 929프레임을 찍고도 원본이 한 장도 남지 않았다(CLAUDE.md 규칙 11).
