### 오프라인 완주를 확인하는 법 (자동 기록 — 2026-08-21 확립)

★**검증하는 사람이 그 노트북의 네트워크로 붙어 있으면 끊는 순간 자기도 끊긴다.**
그래서 눈으로 보는 대신 **스크립트가 기록하게** 하고, 복구 후 파일을 읽어 판정한다.

```powershell
# 1) 카메라를 붙인 상태에서 관측 시작(끊기 전에 먼저 띄운다)
python scripts\offline_probe.py --minutes 10 --min-run 3

# 2) 관측이 시작되면 랜선을 뽑는다(또는 관리자 셸에서)
Disable-NetAdapter -Name "이더넷" -Confirm:$false

# 3) 5분 뒤 복구
Enable-NetAdapter -Name "이더넷"
```

`audit/offline_probe_<시각>.md` 에 판정이 남는다. **통과 조건 4가지**:
연속 오프라인 3샘플 이상 · 전 구간 HTTP 200 · 전 구간 카메라 `ok` · **다운로드 0건**.

> ★`status` 가 `degraded` 여도 **정상이다** — 인터넷이 없으면 텔레그램이 못 나가고
> "미전송 경보 있음 → degraded"(DEPLOYMENT.md §8)가 설계대로다. 봐야 할 것은
> **검출이 살아 있는가** 이지 경보가 나갔는가가 아니다.
>
> 실측 기준선(2026-08-21): 연속 46샘플(3분 46초) 완전 차단 중 `healthy`·`cam ok`·다운로드 0건.

### ★현장에서 헤매지 않도록 — 실전 팁 3가지 (2026-08-21 실증에서 얻음)

| # | 상황 | 알아둘 것 |
|---|---|---|
| **1** | **재시작하면 화면이 빈다** | 로그인 세션은 **메모리에만** 있어 재시작 시 전부 무효화된다. 이미 열어둔 탭은 배경 요청이 401을 받는데 **아무 안내 없이 화면만 비어 보인다**(에러 메시지 없음). → **F5 새로고침 → 재로그인**. 재시작할 때마다 필요하다 |
| **2** | **사람이 없는데 경보가 울린다** | 정지한 물체가 person 으로 오검출된다(실측: 침대·검은 장비를 conf 0.65~0.66으로). 그 자리가 구역에 들어가면 **상시 침입 경보**가 되고, 움직이지 않으니 **무동작(쓰러짐 의심)** 까지 붙는다. → **구역을 그리기 전에 스냅샷에서 사람 없이 잡히는 자리를 먼저 확인하고, 그 영역을 피해서 그린다** |
| **3** | **두 번째 시연에서 알림이 안 온다** | 같은 카메라·같은 규칙은 **300초 억제**가 정상 동작이다(오경보 폭주 방지). 억제된 건수는 다음 알림에 `동일 경보 N건 억제됨` 으로 합산돼 온다. → **재시연은 5분 간격**. 담당자 앞에서 여러 번 보여줘야 하면 미리 `alerts.notify_cooldown_s` 를 낮춰 두고 시연 후 되돌린다(재시작 필요) |
| **4** | ★**숫자가 이상하면 먼저 의심한다** | 현장에서 나온 수치가 "말이 안 되게 나쁘거나 좋으면" 장비 탓하기 전에 **측정이 오염됐는지**부터 본다. 실제 사례: 삭제한 카메라가 `/health` 에 `stopped` 로 남아 `age=40,544초` 를 보고했고, 그게 기준값으로 잡혀 **한계 N 이 6대인데 1대로 나왔다**. → `/health` 의 카메라 목록에 **모르는 항목·정지 항목이 없는지** 먼저 확인하고, 이상하면 서비스를 재시작한 뒤 다시 잰다. **틀린 숫자를 현장 판단 근거로 쓰는 것이 최악이다** |

## 1. CCTV 연결 (도착 직후 — 목표 30분)

1. 노트북을 NVR 과 같은 네트워크에 연결(랜선 우선, 와이파이는 차선)
2. `ping <NVR IP>` → 응답 확인
3. RTSP 주소 조립(질문지 부록 메모) → 서비스에 카메라 등록:
   `POST /cameras {"id":"academy1","source":"rtsp://계정:암호@<IP>:554/<경로>","fps":2,"enabled":true}`
4. **성공하면 이렇게 보인다**: `/health` 에 `academy1: ok`, `last_frame_age_s < 2`
5. **실패 시 볼 로그**: `logs/vigent.log` 에서 `academy1` 검색 —
   `재연결 #n` 반복 = 주소/계정 오류 또는 방화벽 · `기동 실패` = URL 형식 오류.
   대안 순서: ①서브스트림 주소로 교체 ②VLC 로 같은 주소를 열어 카메라 문제/우리 문제 분리
   ③NVR 웹설정에서 RTSP 활성화 여부 확인

## 1-1. ★폰 모니터링 주소 확인 (목표 5분 — 건너뛰지 말 것)

관제는 폰으로 `/health` 를 보는 것이 기본 경로다. 그런데 **노트북 IP 는 어느 인터페이스로
붙었느냐에 따라 바뀐다** — 랜선(학원 CCTV 망)과 Wi-Fi 는 보통 **다른 대역**이고,
학원은 CCTV 망과 사무용 Wi-Fi 를 분리해 두는 경우가 많다. 실제로 준비 단계에서
"노트북은 랜선(192.168.0.x) · 폰은 Wi-Fi(192.168.21.x)" 로 갈려 접속이 안 됐다
(2026-08-20, 대역 불일치가 원인이었다).

1. **노트북 IP 확인** — 여러 개면 어느 인터페이스인지까지 본다:
   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 |
     Where-Object { $_.IPAddress -notmatch '^(127\.|169\.254\.)' } |
     Select-Object IPAddress, InterfaceAlias
   ```
2. **폰이 붙은 네트워크와 대조** — 폰 설정에서 Wi-Fi 이름과 IP 를 본다
   (Android: Wi-Fi → 연결된 네트워크 → 고급 → IP 주소 / iPhone: Wi-Fi → ⓘ → IP 주소).
   앞 세 자리(`192.168.__.`)가 노트북과 **같아야** 한다. 폰이 LTE/5G 면 당연히 안 된다.
3. 같으면 폰 브라우저에서 `http://<노트북IP>:8010/health` → `status: healthy` 확인.
4. **성공하면 이렇게 보인다**: `{"status":"healthy","phase":"ready", ...}`

**대역이 다르거나 안 열릴 때 — 순서대로**

| 상황 | 대응 |
|---|---|
| 폰과 노트북 대역이 다름 | ①노트북을 **폰과 같은 Wi-Fi** 에 함께 붙인다(단, 그러면 CCTV 망과 끊길 수 있으니 노트북에 랜+Wi-Fi 동시 연결이 되는지 확인) ②**휴대용 공유기**를 가져가 노트북·폰을 같은 대역에 두고, CCTV 는 랜선으로 따로 받는다 |
| 같은 대역인데 안 열림 | 공유기의 **AP 격리(client isolation)** 가 유력하다 — 학원/학교 AP 에 흔하다. **폰 핫스팟을 켜고 노트북을 거기 붙여** 재시도하면 원인이 갈린다 |
| 그래도 안 됨 | 방화벽·바인드를 노트북에서 자가 점검: `netstat -ano \| Select-String ":8010"` 이 `0.0.0.0:8010` 인지, `netsh advfirewall firewall show rule name="VIGENT 8010"` 이 있는지. 노트북에서 **자기 LAN IP 로** `curl` 해서 200 이 오면 서버는 정상이고 문제는 네트워크다 |

> ★**최후 수단**: 폰 모니터링이 끝내 안 되면 노트북 화면으로 직접 관제한다 — 시험 자체는
> 진행 가능하다. 다만 "덮어두고 쓴다"는 운용은 포기해야 하므로 담당자와 자리 배치를 조정한다.

> **카메라를 몇 대까지 붙일 수 있나** — 이 노트북 실측 **한계 6대 / 권장 4대**
> (부록 D-2 §카메라 수용량). 학원에서 여러 채널을 한꺼번에 보고 싶다는 요청이 나오면
> **4대까지는 그 자리에서 수락해도 된다.** 그 이상은 검출 지연이 급증하므로
> "장비를 나누거나 채널을 골라야 한다"고 답한다. 병목은 GPU 가 아니라 **CPU** 다.

## 2. 화각 확인 (스냅샷 — 목표 15분)

1. `GET /cameras/academy1/snapshot` 을 브라우저로 열어 확인
2. 체크: ①실습 코스 전체가 화면에 들어오나 ②지게차 동선이 보이나 ③보행 동선(수강생
   대기·이동 구역)이 보이나 ④**실습 코스 위 사람의 박스 높이가 화면의 10% 이상인가**
   (1080p 기준 세로 108px — 스냅샷을 저장해 픽셀로 재면 된다)
3. **성공 기준**: ④ 충족. 미달이면: 더 가까운 채널로 교체 or 지참 카메라 보조 설치 협의.
   ★10% 미달인 채로 진행하면 침입 감지를 신뢰할 수 없다(프레스 현장 실측 근거 —
   height 5~10% 에서 conf 0.61, 활성 임계 0.70 미달)

## 3. 지게차 검출 라이브 확인 (실습 중 — 목표 20분)

1. 실습 지게차가 화면에 있는 상태에서 대시보드 오버레이 확인
2. 기록할 것(나중에 리포트용): ①지게차가 잡히는 프레임 비율(체감이라도) ②표시 conf
   ③라벨(forklift 인지 truck 대용인지) ④추적 id 유지 여부(주행 중 id 가 자주 바뀌는지)
3. **성공하면 이렇게 보인다**: 주행 중인 지게차에 박스가 붙어 따라다니고 conf 가 0.5 이상
   안정적, id 유지
4. **실패 시**: 검출이 아예 없으면 — G1 결론대로 재학습 필요 확정. 이 경우에도 **4단계
   (person 기반 구역 경보)와 5단계(녹화 회수)는 그대로 진행한다** — person 침입 감지는
   지게차 슬롯과 무관하게 성립하고, 회수 영상이 재학습 자산이 된다

## 4. 근접·구역 경보 시험 (목표 30분)

★**안전 수칙: 사람이 지게차에 접근하는 시험은 금지.** 경보 발화는 구역 경계와 실습
지게차의 **기존 동선**만으로 확인한다.

1. 위험구역 폴리곤 지정 — **실습 코스의 일부**를 구역으로 지정.
   **조작 방법은 [부록 A](#부록-a-위험구역-그리기--화면-조작-절차)에 단계별로 적어뒀다.**
   요약: `/safety-hub` 접속 → 카메라 클릭 → **위험구역 편집** → 영상 위 꼭짓점 클릭(3점 이상)
   → **저장**. 저장하면 워커가 자동 재시작되어 즉시 반영된다.
2. **구역 경보(zone_intrusion)**: 실습 휴식 시간에 **강사/담당자 협조**로 한 명이 (지게차가
   정지·이격된 상태에서) 구역 경계를 걸어서 넘는다 → 1.0초 체류 후 경보 발화 확인
3. **근접 경보(proximity_hazard)**: 별도 연출 없이 실습 중 자연 발생을 기다린다 —
   지게차 주변 3m 에 사람이 들어오는 순간(승하차·유도 등)이 실습 중 반드시 나온다.
   ★일부러 만들지 말 것
4. ★**운전자 처리 현장 확인**(G5 — 필수):
   - 실습 중 **운전자 탑승 상태**에서 근접(`proximity_hazard`)·구역(`zone_intrusion`) 경보가
     **울리지 않는지** 10분 이상 관찰 — 울리면 `proximity.driver_containment`(0.65) 재조정
     (학원 CCTV 화각에서 포함률 분포가 실측 영상과 다를 수 있다)
   - **운전자 하차 순간**(교대·휴식 등 일상 동작 — 별도 연출 금지)에 하차한 사람이
     지게차 옆에 있으면 근접 경보가 **다시 울리는지** 확인 — 하차 직후가 협착 최고
     위험이므로 여기서 안 울리면 제외 과잉(임계를 올려야 함)
5. **성공하면 이렇게 보인다**: 이벤트 로그에 `zone_intrusion`(high) / `proximity_hazard`
   (high, "…약 N.Nm") 가 찍히고 텔레그램/웹훅 알림 도착(설정돼 있으면) —
   **단 탑승 운전자에 대해서는 침묵**
6. **실패 시 볼 로그**: `/health` 의 경보 큐 상태(미전송 적체) · `logs/vigent.log` 에서
   `zone_intrusion` 검색. 구역 미발화면: 구역 폴리곤 좌표(정규화 0~1)와 사람 발 위치
   (`zone.reference: foot`) 확인 — 카메라 각도가 높으면 `center` 로 바꿔 재시도

## 5. ★전 과정 녹화 회수 (철수 전 — 필수)

1. 테스트 시간대의 NVR 녹화본을 USB 로 반출(가능하면 실습 전체 시간대) —
   **학원 동의 문구**: "본 영상은 지게차 감지 모델 개선·시험 목적에 한해 사용하며,
   인물 식별 정보는 비식별화 처리 후 보관합니다. 외부 공개하지 않습니다."
2. 반출 불가 시: 서비스가 남긴 증거 프레임(`data/evidence/`)이라도 확보, 부족하면
   현장 직접 촬영 허가 요청
3. 회수본 용도: ①G1 지게차 검출 판정 재실측(근거리·주행 조건) ②재학습 데이터
   ③회귀 시험 자산(파일 카메라 재현 — 1/15 배속 특성 유념)

## 6. 철수 체크리스트

# 부록 A. 위험구역 그리기 — 화면 조작 절차

> ★현장에서 **이 문서만 보고** 따라할 수 있게 적었다(화면 캡처 없음).
> 아래 내용은 2026-08-20 에 개발 PC 에서 파일 카메라로 **전 과정을 실제로 실행해 확인**했다.

## A-0. 먼저: 어느 화면을 쓰나 (★틀린 화면을 쓰면 구역이 엉뚱한 곳에 그려진다)

| 화면 | 주소 | CCTV 구역 그리기에 쓰나 |
|---|---|---|
| **관제 대시보드** | **`/safety-hub`** | ✅ **이것을 쓴다** — 카메라별 구역, 실제 CCTV 영상 위에 그림 |
| 콘솔(safety-pro) | `/safety-pro` | ⛔ **쓰지 말 것** — 아래 경고 |

> ### ⛔ `/safety-pro` 를 현장에서 쓰면 안 되는 이유 (코드 확인)
>
> **① 보이는 영상이 CCTV 가 아니다.** 이 화면은 `getUserMedia` 로 **노트북 내장 웹캠**을
> 띄운다. 거기 그린 구역은 **웹캠 화면 기준 좌표**다 — CCTV 영상과 아무 관계가 없다.
>
> **② 그런데 그 좌표가 실제 CCTV 판정에 쓰인다.** 이 화면은 카메라별이 아니라
> **전역 구역**(`/zone/danger`)에 저장하는데, 워커는 **카메라에 자기 구역이 없으면
> 전역 구역으로 폴백**한다. 즉 현장에서 이 화면을 열어 그리면, 웹캠을 보고 찍은 좌표가
> **`academy1` 의 위험구역이 되어 버린다.**
>
> ★**정정(2026-08-20)**: 이 문서 초판에 "좌표가 좌우 반전돼 저장된다"고 적었으나
> **사실이 아니다.** 화면은 CSS 로 좌우반전(셀카 거울)되지만 클릭 좌표를 되돌리는
> 보정(`fx = 1 - fx`)이 들어 있어 **저장되는 좌표 자체는 올바르다**(코드 주석
> "이중 미러 수정"). 위험한 것은 반전이 아니라 **①·②** 다.

## A-1. 접속과 로그인

1. 노트북 브라우저에서 **`http://127.0.0.1:8010/safety-hub`** 를 연다
   (다른 기기에서 볼 때는 `http://<노트북 LAN IP>:8010/safety-hub`)
2. 로그인 화면이 뜨면 **API 토큰**을 붙여넣고 로그인
   - 토큰은 노트북의 `.env` 파일 `VIGENT_API_TOKEN=` 값이다
   - ★토큰을 문자·메신저로 주고받지 말 것. 화면에서 직접 복사해 붙여넣는다
   - 로그인하면 세션이 유지되므로 이후 화면은 그냥 열린다

## A-2. 그리는 절차 (7단계)

| # | 조작 | 화면에서 확인할 것 |
|---|---|---|
| 1 | 카메라 목록에서 **`academy1`** 을 클릭 | 큰 화면(스포트라이트)에 그 카메라 영상이 뜬다 |
| 2 | 오른쪽 패널에서 **`위험구역 편집`** 버튼 클릭 | 버튼이 `점 지우기` · `취소` · `저장` 3개로 바뀐다 |
| 3 | 안내문 확인 | "영상 위를 클릭해 꼭짓점을 추가하세요(3점 이상)" |
| 4 | **영상 위를 클릭**해 꼭짓점을 하나씩 찍는다 | 클릭할 때마다 점과 선이 그려진다 |
| 5 | 잘못 찍었으면 **`점 지우기`** | **전부 지워지고 처음부터** 다시 찍는다(한 점만 취소하는 기능은 없다) |
| 6 | 모양이 맞으면 **`저장`** | 버튼이 원래대로 돌아가고 구역이 빨간 영역으로 표시된다 |
| 7 | 그만두려면 **`취소`** | 그리던 점이 버려지고 이전 구역이 유지된다 |

### 알아둘 규칙

| 항목 | 값 |
|---|---|
| 필요한 최소 꼭짓점 | **3개** |
| 최대 꼭짓점 | **제한 없음**(코드상 상한 없음 — 실용적으로 4~8개면 충분) |
| 카메라당 구역 개수 | **1개**(폴리곤 하나). 여러 구역이 필요하면 카메라를 나눠야 한다 |
| 저장 위치 | 서버의 카메라 등록 정보(브라우저가 아니다 — 다른 PC 에서 열어도 보인다) |
| 반영 시점 | 저장 즉시. **워커가 자동 재시작**된다(응답의 `restarted: true`) |
| 좌표 방식 | 화면 비율(0~1) — 해상도가 바뀌어도 같은 위치를 가리킨다 |

> ### ⚠ 꼭짓점 2개 이하로 저장하면 조용히 꺼진다
> 서버는 2점짜리도 받아주지만 **판정은 3점 이상일 때만** 동작한다.
> 저장했는데 경보가 안 울리면 **먼저 점 개수를 확인**할 것.

## A-3. 저장됐는지 확인하는 방법 (화면 말고 숫자로)

브라우저 주소창에 다음을 열면 저장된 좌표가 그대로 보인다:

```
http://127.0.0.1:8010/cameras/academy1/zone
```

`{"points":[{"x":0.05,"y":0.55}, …],"count":4}` 처럼 나오면 정상이다.
`count` 가 **3 이상**인지 반드시 확인한다.

## A-4. 구역을 어디에 그릴 것인가 (현장 판단)

- **실습 코스의 일부**만 지정한다 — 코스 전체를 덮으면 운전자·수강생이 상시 침입이 된다
- 사람이 **걸어서 들어갈 수 있는 바닥면**을 감싼다(공중이 아니라 지면 기준)
- 판정 기준점은 **발(박스 하단 중앙)** 이다 — 사람의 발이 구역 안에 들어와야 침입이다
  - 카메라가 거의 수직으로 내려다보면 박스 하단이 발이 아닐 수 있다 →
    이때는 `config/tuning.yaml` 의 `zone.reference` 를 `foot` → `center` 로 바꾼다(재시작 필요)
- 침입 확정에는 **1.0초 체류**가 필요하다(단일 프레임 오검출 차단). 경계를 스치듯 지나가면
  안 울리는 것이 정상이다

## A-5. 지우기 / 되돌리기

| 하고 싶은 것 | 방법 |
|---|---|
| 구역을 다시 그린다 | `위험구역 편집` → `점 지우기` → 새로 클릭 → `저장` |
| 구역을 아예 없앤다 | 편집 모드에서 `점 지우기` 후 바로 `저장`(점 0개 저장) |
| 그리다 그만둔다 | `취소` |

# 부록 B. 근접 경보 반경 바꾸기 (현재 3.0m)

## B-1. 어디를 고치나

노트북의 **`config/tuning.yaml`** 파일을 메모장으로 열어 맨 위쪽 `proximity:` 아래를 고친다.

```yaml
proximity:
  radius_m: 3.0     # ← 이 숫자를 바꾼다 (단위: 미터)
```

## B-2. ★고친 뒤 반드시 서비스를 재시작해야 한다

설정값은 **서비스가 켜질 때 한 번만 읽는다**(메모리에 캐시). 파일만 고치면 바뀌지 않는다.

```
관리자 PowerShell:  Restart-Service VIGENT
```

재시작 후 `/health` 가 `healthy` 로 돌아오는지 확인한다(예열 약 30초).

## B-3. 얼마로 바꿀 것인가 (판단 기준)

| 증상 | 조정 방향 |
|---|---|
| 근접 경보가 너무 자주 울린다 | 반경을 **줄인다**(예: 3.0 → 2.0) |
| 지게차 바로 옆인데 안 울린다 | 반경을 **늘린다**(예: 3.0 → 4.0) |
| 운전자 때문에 상시 울린다 | 반경이 아니라 `proximity.driver_containment`(0.65)를 조정 — 본문 4단계 |
