# 텔레그램 실채널 설정 절차 (2026-08-20 작성)

> 목적: [W1] 로 배선은 끝났으나 **보낼 채널이 없다** — 채널을 붙여 실제 도달을 1회 확인한다.
> [M1] 에서 "실채널 전송 시간 미측정"으로 남은 항목도 이 절차로 채운다.
>
> ★**서비스 재시작이 필요 없다.** 알림 설정은 `notify_cfg()` 가 **호출할 때마다 새로 읽는다**
> (`dispatcher.py:30` — "매번 신선히 읽어 무재시작 반영"). `config/tuning.yaml`(재시작 필요)과
> 다르니 혼동하지 말 것.

---

## 0. 준비 — 무엇이 필요한가

| 필요한 것 | 어디서 얻나 |
|---|---|
| **봇 토큰** | 텔레그램에서 `@BotFather` 에게 봇을 만들면 받는다 |
| **채팅 ID** | 그 봇에게 아무 메시지나 보낸 뒤 API 로 조회 |

---

## 1. 봇 만들기 (텔레그램 앱에서 — 3분)

1. 텔레그램에서 **`@BotFather`** 를 검색해 대화 시작
2. `/newbot` 입력
3. 봇 이름 입력 (예: `VIGENT 안전경보`)
4. 봇 사용자명 입력 — **반드시 `bot` 으로 끝나야 한다** (예: `vigent_safety_alert_bot`)
5. BotFather 가 **토큰**을 준다 — `123456789:AAH...` 형태

> ⚠**토큰은 비밀번호와 같다.** 이 토큰을 아는 사람은 누구나 봇으로 메시지를 보낼 수 있다.
> 채팅·메모·문서에 붙여넣지 말 것. 아래 3단계처럼 **화면에 직접 입력**한다.

## 2. 채팅 ID 알아내기 (2분)

1. 방금 만든 봇을 검색해서 **대화를 열고 아무 메시지나 보낸다**(예: `안녕`)
   - ★이 단계를 건너뛰면 안 된다. 봇은 **먼저 말을 건 사람에게만** 보낼 수 있다.
2. 브라우저 주소창에 아래를 입력(`<토큰>` 자리에 1단계 토큰):

```
https://api.telegram.org/bot<토큰>/getUpdates
```

3. 응답에서 `"chat":{"id":123456789,` 부분의 **숫자**가 채팅 ID 다
   - 개인 대화면 양수, 그룹이면 `-100...` 으로 시작하는 음수다

> **여러 명이 받게 하려면**: 그룹을 만들고 봇을 초대한 뒤, 그룹에서 아무 메시지나 보내고
> 위 `getUpdates` 를 다시 조회한다. 그때 나오는 음수 ID 를 쓴다.

## 3. VIGENT 에 입력하기 (화면에서 — 1분)

브라우저에서 **설정 화면**을 연다:

```
http://127.0.0.1:8010/safety/setup
```

화면 **③ 알림** 항목에서:

- **`텔레그램 Bot Token`** 칸에 1단계 토큰을 붙여넣는다
- **`텔레그램 Chat ID`** 칸에 2단계 숫자를 넣는다
- **`알림 저장`** 버튼을 누른다

저장되면 노트북의 **`config/notify.yaml`** 에 기록된다.

> ★**토큰은 저장 후 화면에 다시 보이지 않는다**(`설정됨` 여부만 표시). 이건 의도된 동작이다.
> 빈 칸으로 저장하면 **기존 값이 유지**되므로, 채팅 ID 만 바꾸고 싶을 때 토큰을 다시
> 입력할 필요가 없다.

### 화면을 못 쓸 때 (파일로 직접)

노트북의 `config/notify.yaml` 을 메모장으로 만들거나 열어서:

```yaml
telegram_token: "123456789:AAH..."
telegram_chat: "123456789"
```

★이 파일은 **평문 자격증명**이다. `.gitignore` 에 이미 등재돼 있다(확인함) — 커밋되지 않는다.

## 4. 도달 확인 (필수 — 1분)

설정 화면 ③ 알림의 **`🔔 테스트 발송`** 버튼을 누르거나, PowerShell 로:

```powershell
$tok = (Get-Content .env | Select-String '^VIGENT_API_TOKEN=').ToString().Split('=')[1]
$h = @{ Authorization = "Bearer $tok" }
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8010/alerts/test -Headers $h `
  -ContentType 'application/json' -Body '{"level":"high","message":"VIGENT 도달 확인"}'
```

**성공 판정**: 응답의 **`delivered: true`** + 텔레그램에 실제 메시지 도착.

| 응답 | 뜻 | 조치 |
|---|---|---|
| `delivered: true` | ✅ 실제 전송됨 | 완료 |
| `delivered: false`, telegram `reason: 미설정` | 토큰·채팅 ID 중 하나가 비었다 | 3단계 재확인 |
| `delivered: false`, `status: 401` | 토큰이 틀렸다 | 1단계 토큰 재확인 |
| `delivered: false`, `status: 400` | 채팅 ID 가 틀렸거나 봇에게 먼저 말을 안 걸었다 | 2단계 재실행 |
| 응답이 없고 오래 걸린다 | 인터넷 차단(현장 방화벽) | §6 참조 |

## 5. 실제 경보로 최종 확인 (권장)

테스트 발송은 API 경로다. **카메라 검출 경로**까지 확인하려면:

1. 위험구역을 그린다([academy_visit_day.md](academy_visit_day.md) 부록 A)
2. 사람이 구역을 걸어서 넘는다 → 1.0초 체류
3. 텔레그램에 `[카메라이름] 위험구역 내 작업자 감지(체류 확정)` 이 도착하는지 확인

★이게 되면 **[W1] 배선이 라이브에서 성립한 것**이다.

### 경보가 너무 자주 오면 (정상 동작이다)

[W1] 폭주 방지가 걸려 있어 같은 카메라·같은 규칙은 **처음 300초, 이후 점점 뜸하게**
(600 → 1200 → … 최대 3600초) 온다. 억제된 건수는 다음 메시지 끝에
`직전 통보 이후 동일 경보 N건 억제됨` 으로 함께 온다.

바꾸려면 `config/tuning.yaml` 의 `alerts.notify_cooldown_s` 등을 조정한다 —
★**이쪽은 서비스 재시작이 필요하다**(알림 채널 설정과 다름).

## 6. 현장에서 인터넷이 막혀 있으면

학원·공장 네트워크가 외부 접속을 막으면 텔레그램은 **못 간다**(`api.telegram.org` 필요).

| 대안 | 방법 |
|---|---|
| **웹훅**(사내망) | 설정 화면의 `webhook_url` 에 사내 수신 주소 입력 — 외부망 불필요 |
| **이메일(SMTP)** | 사내 메일서버를 쓰면 외부망 없이 가능 |
| 확인만 하고 넘어가기 | 경보는 **큐에 pending 으로 쌓인다** — 인터넷이 되는 곳에서 자동 재전송된다([B5]) |

★**경보는 유실되지 않는다.** 전송 실패 시 지수 백오프로 최대 10회 재시도하고,
초과하면 데드레터로 남는다. `/health` 의 `alerts.pending` 으로 적체를 볼 수 있다.
