4. **⚠️ 기존에 보고된 수치(정밀도 89.1%/91.1%, 재현율 56.7%/63.3%, `field_eval_results.md`)는

## 0. 추가 진단 — 놓친 것들의 정체 (실측, 2026-08-08)

**질문**: 놓친 객체들은 "임계를 넘지 못한 것"인가, "모델이 아예 못 본 것"인가?
conf=0.10 초안(`labels_draft/`, 1,574건)에 그 객체가 있었는지로 갈랐다.

| | 놓침(FN) | 그중 conf 0.10 초안에 있었던 것 | 해석 |
|---|---|---|---|
| person | 87건 | **48건 (55.2%)** | 절반은 **임계 문제** |
| PPE | 119건 | **9건 (7.6%)** | 대부분 **모델이 아예 못 봄** |

클래스별로 보면 결론이 더 뚜렷하다:

| 놓친 클래스 | 건수 | 초안에 있던 것 |
|---|---|---|
| NO-Safety-Vest | 54 | 4 |
| **NO-Hardhat** | **53** | **0** |
| Hardhat | 10 | 5 |
| Mask | 2 | 0 |

**`NO-Hardhat`은 53건을 놓쳤는데 그중 conf 0.10 초안에 있던 건 0건이다.**
임계를 아무리 낮춰도 안 잡힌다 — **모델이 이 도메인의 안전모 미착용을 볼 능력이 없다.**

### 객체 크기별 재현율 (박스 면적 / 화면 면적)

| 크기 | person | PPE |
|---|---|---|
| 대(>5%) | 73/94 = 77.7% | 32/33 = **97.0%** |
| 중(1~5%) | 31/87 = 35.6% | 58/94 = 61.7% |
| 소(<1%) | 10/20 = 50.0% | 115/197 = 58.4% |

**PPE 정답의 61%(197/324)가 화면의 1% 미만인 아주 작은 객체**이고, 거기서 재현율이 58%로 떨어진다.
크게 보이면 97% 잡는다 — **모델의 문제라기보다 "너무 작게 들어간다"는 입력 해상도 문제**일 수 있다
(가설 — 검증 필요).

> ★**이 가설은 [Q-2](2026-08-10)에서 실측으로 기각됐다** — 해상도를 올렸더니 오히려 전 지표가
> 나빠졌다(384→1280 순으로 person·NO-Hardhat·PPE 전체 재현율 전부 하락). 위 크기별 표는 여전히
> 사실이지만("작은 객체는 못 잡는다"), 원인이 "해상도 부족"은 아니었다 — 자세한 내용은 P-3-1 항목
> 참고. 진짜 원인(파인튜닝 해상도 불일치 추정)은 미검증.

### [P-1] GPU 확인 — **완료(2026-08-10). GPU 있었음 + CUDA 전환 완료**

**실측**: `nvidia-smi` → NVIDIA GeForce **RTX 5070 Ti**(VRAM 16GB) 확인. 그런데 설치돼 있던 torch는
`2.12.0+cpu`(CPU 전용 빌드)라 `torch.cuda.is_available()=False` — **GPU가 없던 게 아니라 소프트웨어가
못 쓰고 있었다.** 148ms/프레임 CPU 측정치 전부가 이 상태에서 나온 값이었다.

**전환(사용자 승인 후 진행)**: cu126 빌드로 1차 설치했으나 RTX 5070 Ti가 최신 Blackwell(compute
capability sm_120)이라 커널 없음 에러(`no kernel image is available for execution on the device`) —
cu130 빌드(`torch==2.12.0+cu130` · `torchvision==0.27.0+cu130`, 드라이버의 CUDA 13.3과 일치)로
재설치해 해결. `torch.cuda.is_available()=True` + 실제 GPU 행렬곱 실행 확인.

**즉시 효과 확인**: 이 프로젝트의 장치 선택(`vigent-core/device.py` `pick_device()`)은 이미
"CUDA 최우선" 순서였다 — **코드 수정 없이** 자동으로 GPU를 쓴다. `guard.detect(person, imgsz=960)`
10회 실측 median **14ms**(Docker/WSL2 떠 있는 채로 측정, 참고치) — 이전 CPU 148ms 대비 **약 10배**.
테스트 스위트 108개 전부 통과(회귀 없음).

**판단**: GPU 여유가 커서 P-3의 해상도 상향(960→1280·1536)·2단계 크롭 둘 다 지연 걱정 없이
시도 가능하다. **정확한 공식 latency 재측정은 `docs/benchmark_measurement_hygiene.md` 절차
(Docker Desktop 종료 + `wsl --shutdown`) 준수 후 별도로 한다** — 위 14ms는 오염 가능 상태에서 잰
참고치일 뿐 확정치 아님.

### ★[P-2] person 이중 신호 앙상블 — **채택·구현 완료(2026-08-10)**

**근거**: `benchmarks/pilot_conf_threshold_report.md`([L] 조사)에서 PPE 모델 자체의 `Person` 클래스가
person 검출기가 놓친 사람을 잡는 사례를 "사람없음" 17장 중 6장에서 확인했다 — 두 신호(person 슬롯 ·
ppe 슬롯의 Person 클래스)는 현재 합쳐지지 않는다. person 재현율(56.7%, 전체 기준)은 PPE 판정
자체의 병목이다(사람을 못 보면 그 사람의 PPE 판정 대상 자체가 안 생김). 이 실험은 **학습 불필요·
코드 소량·dev로 즉시 채점 가능**해서 P-1 GPU 확인 다음으로 우선순위를 올린다.

**실측 결과**(`benchmarks/p2_person_ensemble.md`, `benchmarks/p2_person_ensemble.py`, dev 74장):
1. 겹침 39.5%뿐(전부가 아님) — B(ppe 슬롯 Person)만 잡는 GT가 15.3% 실재 → 2단계 진행.
2. OR+NMS(IoU≥0.5) 앙상블: **재현율 55.4%→70.7%(+15.3%p), 정밀도 89.7%→79.9%(−9.8%p),
   F1 68.5%→75.0%(+6.5%p)**. 교환비 FP/TP=0.75(오탐 18건으로 정탐 24건 회수) — person 임계
   스윕(오탐 1.6~2.9배 대가)보다 훨씬 유리.
3. **재현율 상승(+15.3%p) > 정밀도 하락(9.8%p) → 기각 기준 미해당, 채택 권고.**
4. 지연: 단순 합산 27.3ms지만, **`worker.py` 확인 결과 PPE 판정용 `do_full` 경로는 이미
   person+ppe를 함께 돌리고 있어 앙상블 추가 비용이 사실상 0**. person 전용 고속 표시 경로
   (`focus_active`, 5fps)는 의도적으로 저비용 설계라 건드리지 않는 게 맞음(표시용, 판정과 무관).

**구현**(`benchmarks/p2_person_ensemble.md` 후반부 상세): guard.py를 확인해보니 교차소스 병합
로직(`_nms`·`_merge_cross_source_person`)이 **이미 존재**했다 — `detectors=["person","ppe"]`를
같이 부르면(운영 경로 `do_full`·`routers/ppe.py`·`routers/safety_core.py`가 이미 그렇게 부름)
ppe 슬롯 Person도 원래 섞여 들어왔다. `field_eval_results.md`의 56.7%가 낮았던 건 `run_eval.py`가
`field_eval_person` 평가에서 `detectors=["person"]` 단일 호출만 했기 때문(방법론 선택, 버그
아님). 그래서 "구현"은 새 알고리즘이 아니라 **기존 동작에 `PERSON_ENSEMBLE` 플래그(기본 `true`,
`config/tuning.yaml` `detect.person_ensemble`)로 이름을 붙이고 끌 수 있게** 한 것 —
`_drop_ppe_origin_person()` 신규 함수, `_cross_validate_ppe` 이후·`_track` 이전에 적용.

**확인1(하류 오탐)**: dev 미착용 검출 116건 중 오탐 12건, "완전 유령"(가짜 person+가짜 미착용)
8건 — **전부 이미 알려진 오탐 영상(`000633827`) 1개에 집중**, 전체 대비 6.9%로 낮아 추가 변형

**확인2(회귀)**: `tests/test_person_ensemble.py` 신규 4개(앙상블 on/off 정상 동작, 추적 안정성,

**남은 일**: test 35장 채점은 P-0 원칙대로 전 실험 종료 후 1회만.
