# T1 위험성평가서 골든셋 (홀드아웃) — safety

> **목적**: T1(Scribe+Copilot) 위험성평가서 출력을 **강사(전문가) 정답·rubric**과 대조해
> **절대 품질 A등급**(rubric ≥ 80/100 · 치명적 오류 0)을 판정하기 위한 **홀드아웃** 평가셋.
> 기존 `eval/golden/`(크레인·밀폐·프레스)은 회귀 베이스라인에 이미 쓰인 세트라 홀드아웃이 아니다.
> 여기 T1 세트는 **제품 튜닝·few-shot에 쓰지 않은 신규 케이스로만** 구성한다.

## 확정/미확정 구분 (2026-07-24)
- **확정(강사 확정)**: 홀드아웃 규모 15케이스 · 도메인 건설5/제조5/화학5 · rubric 배점 30/25/25/10/10 · 치명오류 C1~C4.
- **AI가 채운 것(입력·현행 출력만)**: 시나리오 뼈대(코퍼스 근거) · events(RULE_KB 유효 id) · **현행 Scribe 제품 출력 덤프**(실제 생성, `scribe_output`).
- **미확정 = 강사 채점 대상(빈칸)**: 정답(적정성 O/X·위험수준·법령·감소대책) · rubric 항목별 점수 · 치명오류 C1~C4 판정. **AI가 만들지 않는다.**

## 절대 원칙 (기존 `eval/golden/README.md` 계승)
- **정답은 AI가 작성하지 않는다.** Claude Code는 (a) 시나리오 뼈대, (b) 빈칸 서식(`case_template.json`),
  (c) 현행 제품 출력 덤프까지만 제공한다. **값 확정은 강사**가 한다.
- 정답 법령은 화이트리스트(`vigent-core/../data/legal/statutes.yaml`) 내에서 인용한다.
  화이트리스트 밖 조문이 필요하면 케이스의 `pending_review_citations`에 올린다(지금 지어내지 않음).
- **홀드아웃 보증**: 각 케이스 JSON의 `used_in_training_or_fewshot`은 반드시 `false`.

## 구성 파일
| 파일 | 내용 |
|---|---|
| `RUBRIC.md` | 100점 배점표 + 합격선 + 치명적 오류 체크리스트 (전부 제안값) |
| `case_template.json` | 케이스 1건 빈칸 서식(기존 골든 구조 + rubric·치명오류 블록) |
| `case_index.md` | 홀드아웃 15케이스 **제안 공종 목록**(뼈대만, 정답 없음) |
| `cases/` | 강사 확정 케이스가 채워질 폴더(현재 비어 있음) |

## 척도 (제품·기존 골든과 동일)
- **가능성(빈도) 1~3 × 중대성(강도) 1~3 = 위험성 1~9**, 등급: 상(6~9)/중(3~4)/하(1~2).
- **감소대책 위계**(고시 제12조): ① 제거·대체 → ② 공학적 → ③ 관리적 → ④ 개인보호구.
- 점검항목은 **요건 긍정형**(O=충족/적정, X=미충족/부적정, − = 해당없음).

## 진행 상태
| 단계 | 상태 |
|---|---|
| 공종·규모·배점 확정 | ✅ 완료(15케이스 · 건설5/제조5/화학5 · rubric 확정) |
| 시나리오 + 현행 제품 출력 생성 | ✅ 완료 — `cases/T1_case_01~15_*.json` (`scribe_output`) |
| 강사 정답·rubric 점수·치명오류 채점 | ⬜ **대기(강사 체크포인트)** |

> 재생성: `python3 datasets/goldens/T1/build_cases.py` (결정적 · 현행 제품 출력 갱신).
> 강사는 각 `cases/*.json`의 `강사_정답` 블록(빈칸)만 채운다.
