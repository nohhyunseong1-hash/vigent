- 기준선 개념: 환경 고유 실패는 개수·이름을 기록해 두고 "수정 후에도 똑같이 그것만 실패"를 통과 기준으로 삼는다. (Mac 기준선: 945개 중 실패 5 — PowerShell/BitLocker/학습핀 등 Windows 전용 검사. **Windows 개발기에서는 이 5건이 통과해야 정상.**)
- push 는 대표가 직접. 삭제는 승인분만, 삭제 전 묶음(`{a,b}.py`)·폴더명 패턴으로 참조 재검색.

## 4. 사용법 변경 사항 (오늘 수정으로 바뀐 것 전부)

| 변경 | 내용 |
|---|---|
| **`/healthz` 신설, `/health` 보호** | 토큰 모드에서 `/health`는 로그인(쿠키) 또는 Bearer 필요. 토큰 없이 보는 생존 점검(폰 LAN 등)은 `/healthz`(status·phase만, HTTP 코드 동일). 로컬 무토큰 모드는 변화 없음 |
| 워치독 기본 URL | `watchdog.sh` 기본 점검이 `/healthz`로 변경(`VIGENT_HEALTH_URL`로 재지정 가능). `service_status.ps1`·`verify_service_reinstall.ps1`은 설치 루트 `.env`의 토큰을 자동으로 읽어 Bearer 전송 |
| **WS `?token=` 폐지** | 웹소켓 인증은 Bearer 헤더·세션 쿠키만(쿼리 토큰은 로그에 남아 폐지). 외부 도구가 `?token=`을 쓰고 있었다면 헤더로 바꿔야 함 |
| WS Origin 검사 | 교차 사이트 페이지의 웹소켓 접속 거부. 특수 구성 예외: `VIGENT_WS_ALLOW_ORIGINS=호스트1,호스트2` |
| **카메라 source 허용목록** | 등록 가능: `rtsp(s)://` · 웹캠 번호 · **저장소 또는 `VIGENT_DATA_DIR` 아래의 실재 파일**. `http(s)://`·`exec:` 등 차단(400). 기존 등록분은 재검증 안 함. 다른 위치의 벤치 영상은 `VIGENT_DATA_DIR`로 지정 |
| 무토큰 외부 노출 차단 | `uvicorn --host 0.0.0.0` 직접 실행 등으로 토큰 없이 외부에 열리면 모든 요청 403 + CRITICAL 로그(외부 노출은 반드시 `VIGENT_HOST`+`VIGENT_API_TOKEN` 세트로 기동) |
| 쿠키 Secure | HTTPS(직접 TLS 또는 X-Forwarded-Proto)로 로그인할 때만 Secure 부여. HTTP 로그인 기존대로 |
| /site/config | 응답의 카메라 주소는 마스킹(`rtsp://***:***@...`). 화면에서 그대로 재저장해도 원본 보존. **새 카메라에 마스킹 문자열을 넣으면 400**(전체 주소 입력 필요) |
| /notify/config | 웹훅 주소가 `config/security.json` allowed_webhook_hosts 밖이면 저장 400 + 화면 토스트 |
| **heartbeat 재시도** | 발송 실패일은 날짜 도장을 안 찍고 기본 600초 간격 재시도(`tuning notify.heartbeat_retry_s`). 성공해야 그날 종료. ★A-1 수정으로 이제 **실제로 발송된다** — 첫 실수신 확인 필요 |
| **법령 게이트 fail-closed** | statutes.yaml 미비 시 VLM 생성 조문이 통과되지 않고 "안전관리자 확인 필요(법령 게이트 미로드: 사유)"로 치환 + ERROR 1회. 파일을 넣으면 재시작 없이 즉시 활성 |
| 결함주입 스위치 | `VIGENT_FAULT_STOP_DETECT`는 `'1'`일 때만 켜짐(`0`·`false`는 꺼짐) |
| OpenAPI 기준 | 라우트 110 → **111**(`/healthz` 추가, baseline 재생성, CLAUDE.md 갱신됨) |
| .gitignore | `.mypy_cache/`·`.ruff_cache/` 추가 |
